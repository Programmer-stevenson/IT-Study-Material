Domain 01

Prepare infrastructure for devices

Exam weight: 20–25% · Identity, enrollment architecture, platform enrollment, access control, compliance, and the prerequisites that make Intune management work.
01.1

Microsoft Entra device identity & groups

Core concept

Every Intune scenario starts with identity. Know the difference between Microsoft Entra registered, Microsoft Entra joined, and Microsoft Entra hybrid joined. Registered devices are commonly personal/BYOD. Joined devices use an organizational cloud identity. Hybrid joined devices belong to on-premises AD and are also represented in Entra ID.

Device groups

Intune assignments depend heavily on groups. Static groups have manually controlled membership. Dynamic user/device groups evaluate rules and automatically add or remove members based on supported attributes. Expect scenario questions where the best answer is to target a dynamic device population rather than maintain membership manually.

Ownership & primary user

Ownership (corporate/personal), primary user, join state, and enrollment method can change which assignments or remote actions make sense. Do not assume 'managed' means 'company owned.'

Exam focus

If the requirement says company-owned, cloud-first, users sign in with work credentials, think Entra joined. If it says personal device, user keeps personal sign-in but accesses work apps, think Entra registered/BYOD. If it still requires on-prem AD/GPO, think hybrid.

Term / choiceWhat to remember
RegisteredUsually BYOD / personal ownership; work account is added for SSO and management scenarios.
JoinedCorporate cloud identity; user signs in with Entra credentials.
Hybrid joinedOn-prem AD joined plus Entra representation; supports legacy domain dependencies.

01.2

Windows enrollment into Intune

Automatic enrollment

For supported Windows devices, configure the Intune MDM user scope so targeted Entra users can automatically enroll devices. Enrollment can accompany Entra join and appropriate hybrid scenarios.

Autopilot

Windows Autopilot uses OEM/reseller or administrator-registered device identity to customize OOBE and enroll a device into organizational management. It is modern provisioning—not classic image deployment.

Provisioning packages

Windows Configuration Designer can build .ppkg packages for bulk configuration/enrollment scenarios where a full Autopilot flow is not appropriate.

GPO enrollment

Hybrid organizations can use Group Policy to trigger automatic MDM enrollment for supported domain-joined devices.

Common failures

Check licensing, MDM authority, MDM user scope, enrollment restrictions, device/user limits, network/DNS, stale device objects, OS support, and time synchronization before assuming Intune itself is broken.

Term / choiceWhat to remember
Automatic enrollmentBest when the user/device already has the required Entra relationship and should enroll with minimal manual work.
AutopilotBest for modern corporate Windows provisioning during OOBE.
PPKGUseful for bulk configuration/enrollment or offline-ish setup without maintaining a full image.

01.3

Apple enrollment: iOS, iPadOS & macOS

APNs dependency

An Apple MDM Push certificate is foundational. Intune uses APNs to communicate with managed Apple devices. The certificate must be renewed and maintained correctly.

Automated Device Enrollment

ADE through Apple Business Manager/School Manager is the corporate zero-touch path. Devices can be supervised and forced through organizational enrollment during Setup Assistant.

BYOD

Personal Apple devices can use user-driven enrollment options. The exam may distinguish between full device enrollment and app-level data protection.

Tokens

Know the role of enrollment program tokens and app/content tokens. Expiration or mismatched Apple IDs/tokens can disrupt enrollment or application deployment.

Troubleshooting lens

Verify APNs validity, ABM token sync, enrollment profile assignment, ownership, platform restrictions, user licensing, and device network access.

Term / choiceWhat to remember
APNsRequired communication channel for Apple MDM.
ADECorporate zero-touch Apple enrollment through ABM/ASM.
SupervisionEnables deeper management capabilities on organization-owned Apple devices.

01.4

Android Enterprise enrollment

Personally owned work profile

BYOD model that isolates work apps/data inside a managed work profile while leaving the personal side outside full corporate control.

Corporate-owned fully managed

Organization-owned device intended primarily for work. IT has broad device-level control.

Corporate-owned work profile (COPE)

Company owns the device but permits personal use; work data remains isolated in the managed profile.

Dedicated

Shared/single-purpose devices such as kiosks, line-of-business handhelds, or signage.

Zero-touch

Google zero-touch and Samsung Knox Mobile Enrollment can automate supported corporate enrollment. Managed Google Play integration is central to Android Enterprise app management.

Exam focus

Ownership + intended use determines the enrollment model. 'Company owned but personal use allowed' strongly points to COPE. 'No user, single purpose' points to dedicated.

Term / choiceWhat to remember
BYOD work profilePersonal device with isolated work container.
Fully managedCorporate device, broad organizational control.
COPECorporate device + personal use allowed.
DedicatedShared/single-purpose/kiosk.

01.5

Intune RBAC, scope & administrative governance

RBAC model

Intune RBAC answers: who can perform which actions against which objects. Built-in roles cover common help desk, application, policy, security, and read-only responsibilities.

Scope groups

Scope groups define the user/device population an administrator can manage.

Scope tags

Scope tags limit visibility of tagged Intune objects for delegated administration. Think regional or business-unit administration.

Multi-admin approval

High-impact changes can be designed to require a second authorized administrator to approve the action before it takes effect.

Least privilege

Exam scenarios often reward the most limited role/scope that satisfies the requirement, not Global Administrator.

Term / choiceWhat to remember
RolePermission set.
MembersAdmins receiving the role.
Scope groupsUsers/devices the admin can manage.
Scope tagsTagged objects the admin can see/manage.

01.6

Compliance policies & Conditional Access

Compliance

Compliance policies evaluate device state: encryption, OS version, password, firewall/AV state, jailbreak/root, threat level, and other supported controls.

Actions for noncompliance

A device can be marked noncompliant immediately or after a grace period; notifications and other actions can be staged.

Conditional Access

Compliance alone does not block Microsoft 365 or app access. Conditional Access is the enforcement layer that can require a compliant device, MFA, authentication strength, approved/app-protected clients, or block access.

Defender risk

Microsoft Defender for Endpoint can feed machine risk into compliance, which can then be enforced through Conditional Access.

Safety

When building Conditional Access policies, test deliberately and preserve emergency access. Scenario questions frequently reward report-only/testing and exclusion of emergency accounts.

Term / choiceWhat to remember
ComplianceEvaluates posture.
Conditional AccessControls access based on signals/conditions.
MDE riskCan influence compliance and therefore access.

01.7

Windows Hello for Business, authentication & LAPS

Windows Hello for Business

WHfB replaces password-based interactive sign-in with key/certificate-backed credentials protected by the device. PIN/biometric gestures unlock the key; the PIN itself is not transmitted like a password.

Cloud Kerberos trust

A common modern hybrid deployment model that simplifies on-prem resource access without requiring user certificate deployment for WHfB.

MFA/passwordless

Understand phishing-resistant methods such as FIDO2/security keys and how Conditional Access can require stronger authentication.

Windows LAPS

Randomizes and rotates local administrator passwords and backs them up to supported directories such as Entra ID or Windows Server AD. Retrieval requires the right permissions.

LAPS vs EPM

LAPS protects a local admin credential. Endpoint Privilege Management controls approved elevation while users remain standard users. They solve different problems.

Term / choiceWhat to remember
WHfBPasswordless Windows authentication.
LAPSUnique rotating local-admin passwords.
EPMControlled elevation for standard users.

Domain 02

Manage and maintain devices

Exam weight: 25–30% · Autopilot, Windows 365, configuration profiles, Intune Suite capabilities, remote actions, diagnostics, and lifecycle operations.
02.1

Windows Autopilot & device preparation

Classic Autopilot

Know the major deployment modes: user-driven, self-deploying, and pre-provisioned. Hardware identity/profile assignment and OOBE drive the experience.

Self-deploying

Designed for shared/kiosk-style devices with no user interaction. TPM attestation is a central requirement in supported flows.

Pre-provisioning

Technician/OEM stages applications and policies first, then the user completes their portion. The point is to reduce user wait time.

Enrollment Status Page

ESP can block device use while required apps/policies are installing. A broken blocking app can turn into an Autopilot failure even when enrollment itself is working.

Device preparation

Newer Autopilot device preparation workflows use modern policy/group behavior and are part of the current exam blueprint. Understand the goal and workflow rather than assuming all questions refer only to classic hardware-hash Autopilot.

Troubleshooting lens

Check device registration, assignment, dynamic group evaluation, licensing, network/DNS, time, MDM scope, enrollment restrictions, TPM/attestation, and failing ESP-blocking apps.

Term / choiceWhat to remember
User-drivenEnd user signs in and completes OOBE.
Self-deployingNo user; shared/kiosk scenario.
Pre-provisionedTechnician phase + user phase.
ESPTracks/blocks provisioning until required items complete.

02.2

Windows 365 Cloud PC administration

Concept

Windows 365 delivers persistent Cloud PCs assigned to users. The Endpoint Administrator needs to understand provisioning, policy, image, networking, monitoring, and lifecycle concepts.

Provisioning policies

Connect licensed users, Cloud PC size/image choices, organizational settings, and networking behavior.

Images

Organizations can use gallery images or custom images depending on requirements.

Networking

Know the difference between Microsoft-hosted networking and customer-managed networking concepts where applicable. If customer networking is required, connectivity and DNS dependencies matter.

Lifecycle

Provision, reprovision, resize, restore, troubleshoot, and retire Cloud PCs using supported workflows.

Exam focus

Questions usually test which policy/object controls provisioning or what dependency to inspect when a Cloud PC fails to provision.

02.3

Configuration profiles, Settings Catalog & policy targeting

Settings Catalog

The primary modern interface for granular configuration across supported platforms. Search for individual CSP/MDM-backed settings and assign them to groups.

Templates

Scenario-based templates remain useful for device restrictions, VPN, Wi-Fi, certificates, kiosk, endpoint settings, and other supported workloads.

Administrative templates

ADMX-backed settings provide familiar GPO-style controls. Modern Settings Catalog coverage is broad, so understand both concepts.

Custom OMA-URI

Used when a supported CSP setting is not surfaced through the normal UI and the exact OMA-URI/value type is known.

Imported ADMX

Organizations can import supported custom ADMX/ADML files to expose policy-backed settings.

Group Policy analytics

Import/analyze GPOs to determine which settings have modern management equivalents.

Assignment filters

Dynamically narrow an assignment based on supported device properties without building a separate permanent group.

Conflicts

When two policy surfaces set the same setting differently, devices may report Conflict. Troubleshoot by identifying every policy writing to the same CSP/setting.

Term / choiceWhat to remember
Settings CatalogGranular modern policy surface.
TemplatePre-grouped scenario settings.
OMA-URIDirect CSP path/value.
Assignment filterRuntime include/exclude targeting.

02.4

Certificates, Wi-Fi, VPN & secure access profiles

Trusted certificates

Devices first need to trust the issuing CA chain. Deploy trusted root/intermediate certificates where required.

SCEP

Certificate enrollment through SCEP/NDES-style infrastructure; scalable for device/user certificate issuance.

PKCS

Certificate delivery through supported PKCS connectors/workflows.

Cloud PKI

Microsoft Cloud PKI provides cloud-hosted certificate authority capabilities for supported Intune certificate scenarios, reducing the need to operate on-prem CA infrastructure for some use cases.

Wi-Fi/VPN

Enterprise Wi-Fi and VPN profiles often depend on certificate profiles being deployed first. Scenario order matters: trust chain → identity certificate → Wi-Fi/VPN profile.

Troubleshooting lens

If secure Wi-Fi/VPN auth fails, validate certificate presence, EKU/SAN/subject assumptions, trust chain, connector health, assignment, and clock/time.

Term / choiceWhat to remember
Trusted rootEstablishes trust.
Identity certAuthenticates user/device.

02.5

Intune Suite: EPM, Remote Help, Enterprise App Catalog & Tunnel for MAM

Endpoint Privilege Management

EPM allows standard users to elevate approved tasks under policy instead of granting permanent local administrator membership. Know rule behavior, elevation types, reporting, and the least-privilege purpose.

Remote Help

Enterprise remote support integrated with Entra identity, Intune roles, session control, and auditing. It is not simply 'RDP through Intune.'

Enterprise App Catalog

Catalog-based application management can reduce the work required to package and maintain supported third-party Win32 applications.

Tunnel for MAM

Provides per-app secure access for supported MAM-protected applications on unenrolled devices—useful when the organization wants access to internal resources without full device MDM.

Advanced Analytics

Adds deeper endpoint insights such as anomaly detection, device timeline, resource performance, battery health, and supported real-time querying capabilities.

Remote HelpIdentity-aware enterprise remote assistance.

02.6

Remote actions, diagnostics & troubleshooting

Know the action

Sync requests a policy check-in. Restart reboots. Retire removes organizational management/data while preserving personal data where supported. Wipe is the destructive factory-reset family of actions. Delete removes the management record and is not the same as wiping the endpoint.

Windows-specific resets

Fresh Start and Autopilot Reset solve different rebuild/repurpose scenarios. Read exactly what the question says about keeping enrollment state, user data, and organizational configuration.

Security actions

BitLocker recovery keys and LAPS passwords can be rotated after exposure/retrieval. Defender intelligence updates and other security actions may also be triggered remotely.

Collect diagnostics

Use Intune's diagnostic collection capabilities to retrieve data without relying only on the end user.

Device query

Supported managed Windows devices can be queried with KQL-style device queries for near-real-time inventory/troubleshooting.

Troubleshooting blade

The user-focused troubleshooting experience is useful for checking assignments, enrollment, app deployment, policy and compliance around a specific user.

Service health

If many devices suddenly fail at once, check Intune/Microsoft 365 service health before rebuilding working policies.

Term / choiceWhat to remember
RetireRemove company management/data; preserve personal data where appropriate.
WipeFactory reset / destructive reset.
DeleteRemove the Intune record.
SyncRequest policy/app check-in.

Domain 03

Protect devices

Exam weight: 15–20% · Defender, endpoint security policy, encryption, attack-surface reduction, application control, risk, and update management.
03.1

Endpoint security policy architecture

Endpoint security node

Intune centralizes security policy surfaces such as Antivirus, Firewall, Disk encryption, EDR, Attack Surface Reduction, Account protection, and security baselines.

Overlap risk

Many settings exist in more than one policy surface. A baseline, Settings Catalog profile, and endpoint security policy can collide if they configure the same underlying setting differently.

Security baseline

A Microsoft-recommended bundle of settings. Baselines accelerate deployment but still require review, scoping, testing, and lifecycle/version management.

Exam focus

Choose the policy family that most directly matches the requirement. 'Encrypt drives' → Disk encryption. 'ASR rule' → Attack Surface Reduction. 'Onboard to MDE' → EDR policy. Avoid choosing a broad baseline when the question asks for one narrowly scoped configuration.

Term / choiceWhat to remember
AntivirusDefender AV behavior.
FirewallFirewall profiles/rules.
Disk encryptionBitLocker/FileVault management.
EDRDefender for Endpoint onboarding/config.
ASRAttack-surface controls.

03.3

BitLocker, FileVault & recovery operations

BitLocker

Use Intune Disk encryption or supported settings to configure drive encryption, algorithm, silent enablement behavior, TPM usage, recovery key escrow, and user interaction.

Recovery keys

Recovery material is highly sensitive. Know where administrators/users retrieve keys and when key rotation is appropriate after a key has been disclosed.

Silent enablement

Prerequisites matter. Compatible TPM, Windows edition, enrollment/join state, and conflicting policy can affect silent BitLocker enablement.

FileVault

macOS uses FileVault; Intune can escrow personal recovery keys and report encryption status.

Exam focus

If a support technician displayed a user's BitLocker recovery key, rotating the recovery key is the security-minded follow-up.

Term / choiceWhat to remember
EscrowBack up recovery key to organization-managed directory/service.
RotateGenerate a new recovery secret after exposure.
FileVaultmacOS full-disk encryption.

03.4

Attack Surface Reduction & App Control for Business

ASR rules

ASR rules block behaviors commonly abused by malware—such as risky child-process, script, Office, credential, or executable behaviors depending on the specific rule.

Audit first

Before broad enforcement, organizations commonly evaluate impact using audit/warn modes where supported. Exam questions often favor pilot/testing over reckless all-user enforcement.

Controlled Folder Access

Helps protect designated folders from unauthorized changes by untrusted applications.

App Control for Business

Controls which applications/code are trusted to run. It is broader application allow/control policy, not the same as antivirus.

Troubleshooting lens

A legitimate app can be disrupted by ASR/App Control. Know how to inspect policy assignment, rule state, reports/events, and exclusions or allow policy rather than disabling the whole security layer.

Term / choiceWhat to remember
ASRBlock risky behavior patterns.
CFAProtect folders from unauthorized modification.
App ControlDecide which code is trusted to execute.

03.5

Windows, Apple & Android update management

Update rings

Control Windows Update behavior: deferrals, deadlines, restart experience, notifications, active hours, pause, and rollout behavior.

Feature update policies

Keep devices on or move them to a specific Windows feature release. Think 'target version' rather than general restart behavior.

Quality updates

Monthly security/quality updates. Expedite capability is used when an urgent fix must move faster than the normal schedule.

Driver updates

Intune can manage supported Windows driver update approval/deployment behavior.

Windows Autopatch

Microsoft-managed update orchestration for eligible environments. Know its purpose rather than treating it as just another update ring.

Hotpatch

On supported Windows editions/services, Hotpatch can reduce the number of reboots needed for eligible security update cycles.

Delivery Optimization

Uses peer/cache delivery methods to reduce repeated WAN downloads.

Apple/Android

Intune also manages supported update controls for supervised Apple devices and Android Enterprise corporate scenarios.

Troubleshooting lens

Check safeguard holds, deadlines, policy conflicts, scan/update state, device eligibility, servicing channel/version, connectivity, and Intune reports.

Domain 04

Manage and secure applications

Exam weight: 15–20% · Win32, Store, LOB and Microsoft 365 Apps deployment plus MAM/app protection, app configuration, troubleshooting, dependencies and supersedence.
04.1

Win32 application packaging & deployment

Packaging

Use the Microsoft Win32 Content Prep Tool to wrap source content into an .intunewin package for Intune Management Extension deployment.

Install/uninstall commands

Intune needs silent commands that return predictable exit codes. The portal does not magically make an interactive installer enterprise-ready.

Requirements

Requirement rules determine whether a device is eligible to receive/install the app: OS architecture/version, disk/memory, file/registry/script conditions, and supported custom logic.

Detection

Detection rules answer a different question: is the app already installed successfully? File, registry, MSI product code, and custom scripts can be used. Bad detection logic is one of the most common causes of loops and false failures.

Dependencies

Ensure prerequisite Win32 apps are installed before the primary app.

Supersedence

Define replacement/update relationships between an old app and a new app, optionally uninstalling the superseded app.

Assignments

Required installs automatically; Available is user-initiated through Company Portal; Uninstall targets removal.

Troubleshooting lens

Review assignment, requirement evaluation, detection, IME logs, installer exit codes, system/user context, restart behavior, dependencies, supersedence, network/proxy, and conflicting installs.

Term / choiceWhat to remember
RequirementShould this device receive the app?
DetectionIs the app already installed?
DependencyInstall prerequisite first.
SupersedenceReplace/update older app.

04.4

App protection policies (MAM)

Purpose

App Protection Policies protect corporate data inside supported apps. They can work on enrolled and unenrolled devices, making them central to BYOD.

Data transfer

Control copy/paste, Save As, backups, open-in behavior, and movement between managed and unmanaged apps.

Access

Require PIN/biometric, work credentials, minimum app/OS versions, or other supported conditions.

Conditional launch

Block access or selectively wipe corporate data when conditions are unsafe—such as excessive offline time, jailbroken/rooted state, or high threat level.

Selective wipe

Remove organizational data from protected apps without factory-resetting a personal phone.

Conditional Access

Conditional Access can require approved/protected app conditions in supported scenarios. MAM policy protects the app data; CA enforces access.

Exam focus

If the requirement says 'protect company data on a personal phone but do not enroll/manage the whole phone,' App Protection Policy/MAM is usually the key.

Term / choiceWhat to remember
MDMManage the device.
MAM/APPProtect app data.
Selective wipeRemove corporate app data only.

04.5

App configuration & app troubleshooting

Managed devices

App configuration can be delivered through the MDM channel to apps on enrolled devices.

Managed apps

App configuration can also target supported SDK-integrated/wrapped managed apps and work alongside MAM.

Use cases

Troubleshooting lens

Quiet Time

On supported platforms, Quiet Time can suppress work-related notifications during configured periods—know it as a work/life boundary policy, not as an application deployment feature.

Domain 05

Optimize endpoint operations

Exam weight: 10–15% · PowerShell, Microsoft Graph, reporting, Endpoint Analytics, Remediations, service health, operational troubleshooting, and automation.
05.1

PowerShell & Microsoft Graph automation

Why Graph

Microsoft Graph exposes Intune/Entra resources through APIs so administrators can report, automate, bulk-process, and integrate endpoint-management workflows.

Authentication

Understand the difference between delegated permissions (acting as a signed-in user) and application permissions (app/service identity). Admin consent and RBAC still matter.

Least privilege

A script should request only the scopes/roles it needs. 'Just make it Global Admin' is rarely the best enterprise answer.

Typical tasks

List managed devices, query compliance/app states, export reports, assign policies, manage groups, perform supported remote actions, or build operational dashboards.

Troubleshooting lens

A correct script can still fail because of Graph permission scopes, tenant consent, Intune RBAC, wrong resource endpoint, authentication token, licensing, throttling, or unsupported operation.

Term / choiceWhat to remember
DelegatedApp acts with signed-in user's authority.
ApplicationApp/service identity acts without an interactive user.
RBACStill constrains administration even when Graph auth works.

05.2

Remediations & custom compliance

Remediations

Use a detection script to evaluate a condition and a remediation script to correct it. Packages can run on schedules and report status.

Exit logic

Detection scripts must return meaningful exit codes/output. A common pattern is exit 0 = healthy and exit 1 = issue detected so remediation should run.

Use cases

Repair services, registry state, configuration drift, disk cleanup, stale files, or other repeatable endpoint problems.

Custom compliance

Where supported, custom scripts can evaluate organization-specific conditions beyond built-in compliance settings.

Exam focus

If the requirement says 'detect recurring endpoint issue and automatically fix it with PowerShell,' Remediations is the direct answer.

05.3

Endpoint Analytics & Advanced Analytics

Endpoint Analytics

Measures endpoint/user experience using metrics such as startup performance, application reliability/performance, and device health signals.

Advanced Analytics

Adds deeper insight capabilities depending on licensing—resource performance, anomaly views, device timeline, battery health, and supported device query experiences.

Device query

Allows KQL-style queries against supported corporate Windows devices for near-real-time troubleshooting. It complements, rather than replaces, normal reporting and remote diagnostics.

Operational use

Use analytics to identify populations with slow startup, unstable apps, hardware pressure, or repeated issues instead of troubleshooting one endpoint at a time.

Exam focus

If the question asks to measure user experience or identify slow startup/app reliability patterns, Endpoint Analytics is more appropriate than compliance or Conditional Access.

05.4

Reports, service health & operational monitoring

Built-in reports

Intune exposes device, compliance, configuration, app, enrollment, security, update and other workload reports. The exam often asks which report/monitoring area best isolates the problem.

Export

Reports can often be filtered/exported for operational analysis. Graph may also be used for automated reporting.

Service health

Check Intune/Microsoft 365 service health when a normally healthy tenant experiences widespread failures. Avoid changing production configuration in response to a platform incident.

Message Center

Microsoft 365 communications can announce changes, deprecations, incidents, and admin actions. Operationally, administrators should understand that service changes can affect endpoints.

Compliance drift

Monitor populations moving from compliant to noncompliant and investigate policy changes, threat state, check-in problems, OS/update state, or expired credentials/certificates.

Alerting mindset

Good endpoint operations distinguish one-device failure, assignment failure, network failure, tenant/service issue, and widespread configuration regression.

05.5

Structured Intune troubleshooting methodology

1. Define scope

One user? One device? One group? One platform? Entire tenant? Scope determines whether to start locally or centrally.

2. Confirm prerequisites

License, supported OS, ownership, enrollment state, join state, network access, certificates/tokens, user/device limits.

3. Confirm targeting

Is the correct user/device in the group? Did a dynamic rule evaluate? Is there an assignment filter or exclusion? Is the correct intent used?

4. Check status

Look at per-user/per-device policy/app/compliance status and error codes before making changes.

5. Force/await check-in

Sync where appropriate, understanding that different workloads have different evaluation timing.

6. Inspect endpoint logs

For Windows app deployment, inspect Intune Management Extension and installer logs. For enrollment, inspect MDM/DeviceManagement-Enterprise-Diagnostics-Provider events and join state as appropriate.

7. Check service health

Especially when many otherwise unrelated endpoints fail simultaneously.

8. Change one thing

Avoid shotgun troubleshooting. Make a controlled change, document expected result, retest, then continue.

ScopeHow widespread is the issue?
TargetingShould this device/user receive the object?
StatusWhat exact error/state is reported?
EvidenceLogs, diagnostics, reports, service health.

Hands-on

Hands-on lab checklist

The exam rewards administrators who understand how these objects interact, not just definitions.

1. Identity & enrollment

Create a test Entra user and device group. Join a Windows VM to Entra ID, confirm Intune enrollment, inspect device ownership/primary user, trigger a sync, and document what changes in both Entra and Intune.

2. Compliance + Conditional Access

Build a pilot compliance policy requiring basic security state. Then design a Conditional Access policy that requires a compliant device. Explain why the first policy evaluates posture and the second enforces access.

3. Autopilot flow mapping

Even if you cannot enroll production hardware, draw the full user-driven, self-deploying, and pre-provisioned flows. Identify where hardware identity, group assignment, deployment profile, ESP, Entra join, MDM enrollment, apps, and policies occur.

4. Settings Catalog + conflicts

Create two pilot configuration profiles, then intentionally configure one overlapping setting differently. Review device status and learn where conflicts surface.

5. Win32 application

Package a harmless test installer as .intunewin, configure silent install/uninstall commands, requirements, detection, assignment, then intentionally break the detection rule and troubleshoot the resulting behavior.

6. MAM / app protection

Design a BYOD app protection policy that requires a PIN, limits copy/paste, blocks saving corporate data to personal locations, and supports selective wipe.

7. Endpoint security

Build pilot Defender AV, Firewall, Disk Encryption, and ASR policies. Explain why security baseline overlap can create conflicts.

8. Windows updates

Create a Pilot ring and a Production ring, then compare them with a Feature Update policy and expedited Quality Update. Be able to explain which object you would change for each requirement.

9. PowerShell + Graph

Use Microsoft Graph PowerShell to authenticate and list managed devices or users. Export selected fields to CSV and document the permission scopes used.

10. Remediation

Write a detection script for a simple state such as a service or registry value. Write a remediation script that fixes the state. Run locally if tenant licensing does not allow Intune Remediations.

11. Troubleshooting drill

Choose one device and trace a problem through enrollment state, group targeting, assignment filters, policy/app status, sync, local logs, remote diagnostics, reports, and service health.
