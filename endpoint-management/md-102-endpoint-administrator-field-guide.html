Domain 01

Deploy the Windows client

Exam weight: 25–30% · Imaging vs. modern provisioning, Autopilot end-to-end, MDT & ConfigMgr task sequences, activation and editions.
1.1

Prepare for a Windows client deployment

Before choosing tools, decide between two fundamentally different paths and let requirements drive the answer.

Migrate vs. rebuild ("wipe-and-load")

  • In-place upgrade / migrate — keeps apps, settings, and user data. Fastest, lowest user disruption. Use when hardware stays and the existing image is healthy. Driven by Windows Setup or a ConfigMgr in-place upgrade task sequence.
  • Rebuild / wipe-and-load — deploys a clean image, then restores user state. Use for new hardware, corrupted installs, or moving from BIOS→UEFI / x86→x64. User data is captured and restored with the User State Migration Tool (USMT) via ScanState and LoadState.

Imaging vs. modern provisioning

ApproachWhat it isBest when
Traditional imagingBuild & capture a reference .wim, deploy with MDT/ConfigMgr task sequences over the network or USB/PXE.On-prem, full control of the image, large refresh projects, no internet at deploy time.
Modern provisioningShip the OEM image as-is; Autopilot + Intune transform it on first boot. No custom image to maintain.Cloud-managed, remote/ship-to-user, "drop-ship" scenarios, minimizing image maintenance.
Provisioning packages.ppkg files built in Windows Configuration Designer (WCD) apply bulk settings/enrollment without re-imaging.Quick bulk enrollment, kiosk setup, or tweaking an existing install offline.
▲ Exam discriminator

"Minimize image maintenance / ship directly to remote users" → Windows Autopilot. "Need full control of the OS image, on-prem PXE" → MDT/ConfigMgr task sequence. "Apply settings to existing devices without reimaging" → provisioning package (.ppkg) from Windows Configuration Designer.

1.2

Plan & implement Windows Autopilot

Autopilot customizes the out-of-box experience (OOBE) so a device that ships from the OEM transforms into a fully-managed, business-ready PC the first time it connects to the internet — no custom image required.

The end-to-end flow

  1. Register the device — its hardware hash (a.k.a. hardware ID, a 4K string derived from the device) is uploaded to Autopilot. Sources: OEM/reseller registers at purchase, an Intune partner, or you collect it yourself.
  2. Assign a deployment profile — targets a device group (often a dynamic group keyed on the Autopilot ZTDID / order ID / group tag).
  3. User powers on → connects to network → Autopilot recognizes the device, applies the profile, and drives Entra join + Intune enrollment automatically.
  4. Enrollment Status Page (ESP) blocks the desktop until required apps, policies, and certs land.
◇ Portal path

Register & manage at Intune admin center → Devices → Enrollment → Windows → Windows Autopilot deployment profiles / Devices. (Historically under Devices → Windows → Windows enrollment.)

Collecting the hardware hash yourself

PowerShell# Install the community script from the PowerShell Gallery
Install-Script -Name Get-WindowsAutopilotInfo -Force

# Export this device's hardware hash to CSV
Get-WindowsAutopilotInfo -OutputFile .\AutopilotHWID.csv

# Collect AND upload straight into Intune (interactive sign-in)
Get-WindowsAutopilotInfo -Online

The CSV columns are Device Serial Number, Windows Product ID, and Hardware Hash. Import via Autopilot devices → Import.

Deployment modes — know these cold

ModeWho completes itKey traits
User-drivenThe end user, at their location.User signs in with their own Entra credentials; device joins as Entra join or Entra hybrid join. Most common.
Self-deployingNobody — zero user interaction.Great for kiosks/digital signage/shared devices. Requires TPM 2.0 for attestation. No user assigned.
Pre-provisioned (was "white glove")IT/OEM provisions the heavy apps; user finishes.Splits into a technician phase (lands apps/policies) and a user phase. Slashes the user's wait time. Hardware attestation required.
Autopilot for existing devicesConfigMgr task sequence.Wipe-and-load an existing domain PC into an Autopilot/Entra-managed state using an offline AutopilotConfigurationFile.json.
▲ Exam discriminator

Self-deploying and pre-provisioning both require TPM 2.0 (device attestation). If a question says "no user interaction / shared kiosk device," answer self-deploying. If it says "reduce the time the user waits while IT pre-loads apps," answer pre-provisioned / white glove.

Enrollment Status Page (ESP)

The ESP shows provisioning progress and can block device use until required apps and profiles install. Configure: show progress, block until complete, allow/block retry & reset, allow use on failure, and which blocking apps must succeed. There's a default ESP plus assignable custom profiles.

Join type set by the profile

  • Entra join — cloud-only identity; the default modern target.
  • Entra hybrid join — also joins on-prem AD. Requires the Intune Connector for Active Directory (creates the AD computer object) and line-of-sight to a domain controller during OOBE.
✕ Common Autopilot failures

Device not registered (hash never uploaded) · profile not assigned before first boot (assign before OOBE) · no network/DNS to reach Entra & Intune · MDM auto-enrollment not enabled in Entra · hybrid join missing the Intune Connector or DC line-of-sight · ESP timeout from a slow/failing blocking app.

1.3

Deploy with MDT & Configuration Manager

The classic on-prem imaging path. Both build on the Windows Assessment and Deployment Kit (ADK) and WinPE.

Deployment scenarios & touch levels

TermMeans
LTI — Lite Touch InstallationMDT alone. One manual kickoff at the target, then automated. Uses a deployment share.
ZTI — Zero Touch InstallationConfigMgr (often with MDT integration). Fully automated, enterprise scale, PXE.
UDI — User Driven InstallationConfigMgr + MDT wizard that lets a technician choose options at deploy time.

Core MDT building blocks

  • Deployment share — repository for OS images, apps, drivers, packages, and task sequences.
  • Task sequence — ordered steps that partition disk, apply the image, inject drivers, install apps, and join the domain.
  • Reference image — built & captured ("build and capture") then deployed; thick (apps baked in), thin (apps layered after), or hybrid.
  • Boot image (WinPE) — the lightweight environment that runs the task sequence.
  • MDT database / rules — CustomSettings.ini and Bootstrap.ini automate prompts.

Configuration Manager adds

  • PXE-enabled distribution point for network boot; boot media (USB/ISO) for offline.
  • Device collections as deployment targets; driver packages and OS image packages.
  • Co-management — a Windows device is managed by ConfigMgr and Intune simultaneously, with workloads sliding from ConfigMgr to Intune (pilot → all).
◆ Co-management workloads

Movable sliders include: Compliance policies, Device configuration, Endpoint Protection, Resource access policies, Client apps, Office Click-to-Run apps, Windows Update policies. Move them Pilot Intune first, then Intune for all.

1.4

Editions, activation & subscription

Pick the edition

EditionWhy choose it
Windows ProBaseline business edition; supports Entra join & MDM. Min for cloud management.
EnterpriseAdvanced security & management: AppLocker, Credential/Application Guard, DirectAccess, full delivery optimization, Modern BitLocker management. Reached via Subscription Activation.
Education / Pro EducationAcademic equivalents of Enterprise/Pro.
LTSCLong-Term Servicing Channel — no feature updates, for fixed-function devices (medical, ATM). Not for general office use.

Activation methods

  • Subscription Activation — a user with a Windows Enterprise E3/E5 license signs in and the device steps up from Pro → Enterprise automatically; steps back down when the license is removed. No keys to manage.
  • KMS (Key Management Service) — on-prem activation host; clients re-activate every 180 days. Needs the activation threshold met.
  • Active Directory–Based Activation — activates domain-joined devices via AD; no separate KMS host count.
  • MAK (Multiple Activation Key) — one-time activation against Microsoft; good for disconnected devices.
▲ Exam discriminator

"Users have Windows Enterprise E3/E5 and you want Pro devices to become Enterprise on sign-in, no keys" → Subscription Activation. "Activate many on-prem domain devices automatically" → AD-Based Activation or KMS. "Activate a handful of offline devices" → MAK.

Domain 02

Manage identity & compliance

Exam weight: 15–20% · Authentication, Entra join & registration, Windows LAPS, Intune RBAC, compliance policies, Conditional Access.
2.1

Manage identity & authentication

Windows devices authenticate against Microsoft Entra ID (formerly Azure AD), on-prem AD, or both. Strengthen sign-in with passwordless options.

Passwordless & modern auth on Windows

  • Windows Hello for Business (WHfB) — replaces passwords with a PIN or biometric tied to the device via asymmetric keys / certs. Deployment models: cloud Kerberos trust (recommended/simplest), key trust, and certificate trust.
  • FIDO2 security keys — phishing-resistant hardware keys for passwordless sign-in.
  • Microsoft Authenticator — passwordless phone sign-in and MFA.
  • Multi-factor authentication (MFA) — enforced best via Conditional Access; "security defaults" turns on baseline MFA tenant-wide.
▲ Exam discriminator

For a cloud-only or hybrid org wanting the simplest WHfB rollout, choose cloud Kerberos trust — it avoids deploying a PKI/certificate infrastructure and uses Entra Kerberos for on-prem resource access.

Self-Service Password Reset (SSPR)

Lets users reset/unlock their own accounts after registering authentication methods (phone, email, security questions, Authenticator). Combine with password writeback (via Entra Connect) so resets sync back to on-prem AD.

◇ Portal path

Entra admin center → Protection → Password reset — set scope (None / Selected group / All), required methods, and registration.

2.3

Windows LAPS

Windows Local Administrator Password Solution automatically randomizes and rotates the built-in local admin password and backs it up securely — eliminating shared/static local admin passwords. It's now built into Windows (no separate MSI for current builds).

  • Backup directory: Microsoft Entra ID (cloud) or Windows Server Active Directory (on-prem).
  • Managed via Intune: an Account protection / endpoint-security LAPS policy sets rotation interval, password length/complexity, and the account to manage.
  • Retrieve the password: in Entra, on the device blade → Local administrator password recovery (requires the right role/permission). Reading it can force an immediate rotation.
◇ Portal path

Intune admin center → Endpoint security → Account protection → Create policy → Local admin password solution (Windows LAPS).

2.4

Intune role-based access control (RBAC)

RBAC controls who can do what, to which objects. An assignment binds three things together:

  • Role — permission set (built-in or custom).
  • Members — the admin group that gets the permissions.
  • Scope (groups + scope tags) — which devices/users they manage and which tagged objects they see.

Built-in Intune roles (examples)

RoleScope of power
Help Desk OperatorRemote tasks, assign apps/policies — day-to-day support.
Policy and Profile ManagerManage compliance & configuration profiles, baselines.
Application ManagerManage apps and app protection/configuration policies.
Endpoint Security ManagerSecurity baselines, endpoint security tasks.
Read Only OperatorView only.
Intune Role AdministratorManage roles & assignments.
◆ Scope tags

Scope tags filter visibility (e.g., region-based admins only see their region's devices/policies). They're attached to objects and to RBAC assignments — useful for delegated, geographically split administration.

2.5

Compliance policies

A compliance policy defines the rules a device must meet to be considered healthy (minimum OS version, encryption on, AV/firewall on, no jailbreak/root, password requirements, threat level). The result feeds Conditional Access.

Common compliance settings by platform

CategoryExamples
Device healthRequire BitLocker, Secure Boot, Code integrity; block rooted/jailbroken devices.
Device propertiesMin/max OS version, build ranges.
System securityPassword/PIN length & type, encryption, firewall, real-time AV, Defender, min security patch level.
Microsoft Defender for EndpointRequire device machine risk score at or under a level (Clear/Low/Medium/High).

Built-in vs. assigned compliance & "not evaluated"

  • There is a tenant-wide built-in compliance policy — when no policy is assigned, you decide whether unassigned devices are treated as compliant or not compliant via Compliance settings → Mark devices with no compliance policy assigned.
  • Set the Compliance status validity period (days a device can go without checking in before being marked non-compliant).

Actions for noncompliance

Each policy can stage graduated actions on a schedule: mark noncompliant immediately or after N days, send email to the user, send push notification, remotely lock, or retire the device after a grace period.

▲ Exam discriminator

Compliance policy alone reports health — it does not block access. To actually block a noncompliant device from resources, you must pair it with a Conditional Access policy that requires "device to be marked as compliant."

2.6

Conditional Access (CA)

CA is the policy engine that evaluates signals and enforces decisions. Think: if these conditions, then grant/block with controls.

Assignments (the "if")Access controls (the "then")
Users / groups / roles · Target resources (cloud apps) · Network & locations · Device platforms · Client apps · Device filters · Sign-in riskGrant: require MFA, require compliant device, require Entra hybrid join, require approved client app / app protection policy, require password change. Block access. Session: app-enforced restrictions, sign-in frequency.
◇ Portal path

Entra admin center → Protection → Conditional Access → Policies → New policy. Always test with Report-only mode first, and keep an emergency break-glass account excluded.

✕ Watch out

CA "require compliant device" needs devices that are Entra registered or joined (so Intune can report compliance). Always exclude a break-glass admin account so a misconfigured policy can't lock everyone out.

3.1

Enroll → configure → protect → monitor → remove. Know the four removal actions cold — they are constantly tested.

Retire = remove company data only (personal kept) → BYOD. Wipe = full factory reset → corporate/lost/stolen. If the question stresses "keep the user's personal photos," it's Retire.

Policy sets bundle apps, policies, and profiles into one assignable unit so onboarding a group applies everything at once.

3.2

Enrollment across platforms

Enrollment restrictions (two kinds)

  • Device platform restrictions — allow/block platforms (iOS, Android, Windows, macOS), set min/max OS versions, and block personally-owned devices.
  • Device limit restrictions — cap how many devices a user can enroll (1–15).

Windows

  • Automatic enrollment via Entra MDM scope (covered in 2.2) — for Entra join / hybrid join.
  • Bulk enrollment with a provisioning package (WCD) using a bulk token.
  • Autopilot for OOBE-driven enrollment.
  • Group Policy can trigger auto-enrollment of hybrid-joined devices.

Apple (iOS/iPadOS & macOS)

  • Apple MDM push certificate (APNs) is mandatory before any Apple device can enroll — renew annually.
  • Automated Device Enrollment (ADE) — formerly DEP — corporate-owned devices bought through Apple Business Manager / Apple School Manager; supervised, zero-touch, enforced enrollment via an enrollment profile + ADE token.
  • Apple Configurator — enroll via USB with a setup-assistant or direct profile.
  • BYOD — user-initiated via Company Portal / web (account-driven for iOS).

Android

Management modeOwnership / use
Personally-owned work profile (BYOD)Personal device; a separate, isolated work profile holds company apps/data.
Corporate-owned, fully managedCompany device, single use, fully controlled — no personal profile.
Corporate-owned with work profile (COPE)Company device that also allows personal use, with a managed work profile.
Corporate-owned, dedicated (kiosk)Single-purpose / shared device — kiosk, signage, line-of-business handheld.

All Android Enterprise modes require a one-time Managed Google Play connection between Intune and your enterprise Google account.

3.3

Configuration profiles

Configuration profiles push settings (Wi-Fi, VPN, certificates, restrictions, browser config, OEM controls) to devices. Choose the right profile type:

Profile typeWhat it's for
Settings catalogThe modern, granular menu — search and pick individual settings. Microsoft's recommended starting point for Windows/macOS/iOS.
TemplatesPre-grouped scenarios: Wi-Fi, VPN, Email, Certificates (SCEP/PKCS/trusted root), Device restrictions, Endpoint protection, Edition upgrade, Kiosk, etc.
Administrative templates (ADMX)GPO-style ADMX-backed settings delivered from the cloud — familiar to AD admins. (Settings catalog now supersedes most of these.)
Custom (OMA-URI)Push a CSP setting not surfaced in the UI by specifying its OMA-URI path/value/data type.

Certificates

  • Trusted root certificate — distribute your root CA (prerequisite for SCEP/PKCS).
  • SCEP — issues device/user certs via a SCEP/NDES connector; great for scale.
  • PKCS — certs issued directly from an enterprise CA via the PKCS connector.

Assignment & filters

Assign to user or device groups (Include/Exclude). Assignment filters add rules (e.g., deviceModel, OS version, ownership) to narrow a broad group at assignment time. Resolve conflicts: explicit settings can clash — Intune flags conflict states; the last/most-restrictive may win depending on setting.

◆ Troubleshooting profiles

Check Device → Monitor for per-setting status (Succeeded/Error/Conflict/Pending). On the client, Settings → Accounts → Access work or school → Info → Sync forces a check-in. Use Troubleshooting + support blade to view assignments for a user.

3.4

Kiosk mode, Android profiles & Microsoft Tunnel

Windows kiosk

  • Single-app kiosk — locks the device to one UWP/Edge app under an auto-logon local account; ideal for signage/check-in.
  • Multi-app kiosk — a restricted Start menu of allowed apps (uses AssignedAccess CSP).

Microsoft Tunnel

Microsoft Tunnel is a VPN gateway that runs in a Linux container and gives iOS/iPadOS and Android managed devices secure access to on-prem resources. Needs the Tunnel Gateway server, a Server configuration, a Site, and the Microsoft Defender app (or Tunnel client) plus a VPN profile pushed from Intune.

3.6

Device updates (Windows Update for Business)

Intune drives Windows Update for Business (WUfB) — no WSUS infrastructure. Three Windows update objects:

ObjectControls
Update ringsDeferral periods, deadlines, active hours, restart behavior, and which quality/feature updates devices receive. Build rings (Pilot → Broad) for staged rollout.
Feature updatesPin a target Windows feature version (e.g., stay on 23H2) and roll it out on a schedule.
Quality updates (expedite)Expedite a critical/security patch to deploy ASAP, overriding deferrals.
Driver updatesApprove or auto-approve driver/firmware updates from Windows Update.

Servicing channels & rollback

  • General Availability Channel — annual feature updates (standard business).
  • LTSC — no feature updates, long support (special-purpose only).
  • Uninstall behavior + deadline grace periods let you recover from a bad patch.

Delivery Optimization

Delivery Optimization reduces bandwidth by letting devices share update/app content peer-to-peer (LAN, group, or cloud). Tune download mode (HTTP only, LAN, group, internet peering) and set group IDs to bound the peer mesh.

Apple & Android updates

  • Apple: create update policies for supervised/ADE devices to push and schedule iOS/iPadOS/macOS OS updates and delay visibility of new releases.
  • Android (Enterprise): set system update behavior (automatic, postpone up to 30 days, maintenance window) for fully managed/dedicated devices.
▲ Exam discriminator

"Get a single urgent security fix out now, bypassing the ring's deferral" → Expedite a quality update. "Keep devices on a specific Windows version and prevent moving to the next feature release" → Feature update profile. "Cut WAN bandwidth during a rollout" → Delivery Optimization.

3.8

Encryption & security baselines

BitLocker via Intune

  • Deploy through a Disk encryption endpoint-security policy (or a device-config Endpoint protection template).
  • Set drive type (OS / fixed / removable), encryption method (e.g., XTS-AES 256), and require TPM.
  • Recovery keys escrow to Entra ID automatically; retrieve via the device blade or have users use the Company Portal / aka.ms/myrecoverykey.
  • FileVault is the macOS equivalent, with personal recovery key escrow.

Security baselines

A security baseline is a Microsoft-recommended, pre-configured group of settings (for Windows, Defender for Endpoint, Edge, Windows 365, etc.). Deploy it, then customize. Baselines are versioned — you may need to upgrade a profile to a newer baseline version. Watch for conflicts when multiple baselines/profiles target the same device.

✕ Baseline conflicts

If two baselines or a baseline + config profile set the same setting differently, the device shows a conflict and the setting may not apply. Standardize on one baseline per scope and layer carefully.

4.3

App protection policies (MAM)

App protection policies (APP) — also called Mobile Application Management (MAM) — protect company data inside an app without managing the whole device. They work on enrolled and unenrolled (MAM-WE) devices, which makes them the go-to for BYOD.

What APP can enforce

  • Data relocation: block copy/paste, "Save As," and backup to personal locations; restrict cut/copy/paste between managed and unmanaged apps.
  • Access requirements: require an app PIN or biometric, corporate credentials, min OS/app version, block on jailbroken/rooted.
  • Conditional launch: wipe company data or block after N failed PIN attempts, offline grace period, or max device threat level.
  • Selective wipe: remove only the corporate data within the app, leaving personal data untouched.
▲ Exam discriminator

"Protect company data on personal phones without enrolling/managing the whole device" → App protection policy (MAM). APP requires apps built with the Intune App SDK / wrapped (most Microsoft mobile apps qualify). Pair with a CA "require approved client app or app protection policy" grant.

4.4

App configuration policies

App configuration policies (ACP) pre-set an app's settings (server URLs, sign-in hints, feature toggles) so users don't configure them manually. Two delivery channels:

TypeDelivered toRequires
Managed devicesApps on enrolled (MDM) devices.Device enrolled in Intune; uses the OS config channel.
Managed appsApps governed by an app protection policy (works without enrollment).App supports the Intune App SDK; pairs with MAM for BYOD.

Example: pre-configure the Outlook app with the user's mailbox and block other accounts; or set the Edge mobile homepage/allowed-account org policies.
