Complete Commands & Theory Reference

Every command explains what it does, why it matters, and what trips people up. Use the sidebar to jump around, or read it straight through. Aimed at passing the 200-301 exam and being competent on day one of the job.

01 Cisco IOS & the CLI

Cisco IOS (Internetwork Operating System) is the software that runs on most Cisco routers and switches. You interact with it through a hierarchical CLI. Everything in your career as a network admin starts here, so build muscle memory for these basics.

The Modes — and Why They Exist

IOS uses different modes so dangerous commands can't be run accidentally. Each mode has its own prompt and command set. You move down into deeper modes and back up with exit or end.

ModePromptEnter WithWhat You Can Do
User EXECR1>(default after login)View limited info, ping, traceroute
Privileged EXECR1#enableAll show commands, debug, reload, save
Global ConfigR1(config)#configure terminalDevice-wide settings: hostname, users, routing
Interface ConfigR1(config-if)#interface gi0/0Per-interface settings: IP, speed, switchport
Line ConfigR1(config-line)#line vty 0 4Console, VTY (SSH/Telnet), aux line settings
Router ConfigR1(config-router)#router ospf 1Routing-protocol settings

The mode hierarchy is a safety boundary. A junior admin can't accidentally erase a config from User EXEC. Knowing which mode a command belongs to is a real exam skill — many wrong answers on the test are valid commands in the wrong mode.

The Help System — Use it Constantly

R1# ? ! list every command available in this mode R1# show ? ! list all show-command options R1# show ip ? ! drill down further R1# sh[Tab] ! Tab completes the command R1# show int br ! abbreviations work if unambiguous R1(config)# do show ip route ! "do" runs an EXEC command from config mode
PRO MOVEdo is huge for daily work. You're in config mode, you want to verify something with a show command — instead of exiting and re-entering, prefix it with do.

Editing & Recalling Commands

  • Up/Down arrow — scroll through command history.
  • Ctrl+A — jump to start of line. Ctrl+E — jump to end.
  • Ctrl+U — clear the line. Ctrl+W — delete the previous word.
  • Ctrl+Shift+6 — break out of a hung ping or traceroute (the "escape sequence").
  • show history — recent commands. terminal history size 50 — increase the buffer.

Configuration Files — running-config vs startup-config

A Cisco device stores its config in two places:

  • running-config — lives in RAM, is the active config. Every command you enter changes this immediately.
  • startup-config — lives in NVRAM, loaded at boot. Survives a reload.
The number-one mistake junior admins make: they configure a device, walk away proud, the device reboots, and the entire config is gone — because they never copied running-config to startup-config. Always save your work.
R1# show running-config ! the active config R1# show startup-config ! what loads at boot R1# copy running-config startup-config ! save (most common) R1# write memory ! older shorthand — same thing R1# wr ! shortest form, very common in practice R1# erase startup-config ! wipe NVRAM (factory reset on next boot) R1# reload ! reboot the device

Negating Commands with "no"

Almost every config command is undone by typing no in front of it. shutdown shuts an interface; no shutdown brings it up. ip address 10.0.0.1 255.255.255.0 sets it; no ip address removes it. This pattern is universal.

02 Initial Device Setup

First commands you run on every new device, in order. This is the "baseline hardening" that turns a factory-fresh switch into a manageable, secured node on your network.

Hostname & Identity

Switch> enable Switch# configure terminal Switch(config)# hostname BR1-SW-01 BR1-SW-01(config)# banner motd # Authorized access only. Activity is monitored. #
WHYA meaningful hostname shows up in show cdp neighbors outputs across your whole network — naming consistency saves you in an outage. The MOTD (message of the day) banner is a legal requirement in many jurisdictions for prosecuting unauthorized access. Never use a "welcome" message — that implies invitation.

Passwords — the Right Way

R1(config)# enable secret StrongP@ss123 ! privileged-mode password (HASHED) R1(config)# service password-encryption ! obscures any plaintext passwords in config R1(config)# security passwords min-length 10 R1(config)# login block-for 120 attempts 3 within 60 ! lockout after brute force
CommandStrengthUse?
enable passwordClear text (type 0) or weak Vigenère (type 7)Never

username X password YClear text by defaultAvoid
username X secret YHashedAlways
🔒
Real-world warning: service password-encryption uses Cisco type 7, which is trivially decryptable — there are websites that crack it in milliseconds. It hides shoulder-surfing, not a determined attacker. Real protection comes from using secret (hashed) commands and not letting unauthorized users see configs in the first place.

Console & VTY Lines

Lines are how people connect into the device. Console = physical port (rollover cable). VTY = virtual lines for SSH/Telnet (usually 0–4, sometimes 0–15).

R1(config)# line console 0 R1(config-line)# password ConsoleSecret R1(config-line)# login R1(config-line)# exec-timeout 10 0 ! auto-logout after 10 min idle R1(config-line)# logging synchronous ! stop log msgs from breaking your typing R1(config)# line vty 0 4 R1(config-line)# transport input ssh ! SSH only, no Telnet R1(config-line)# login local ! authenticate against local user database
EVERY-INTERFACE PRO TIPlogging synchronous is the single best quality-of-life command. Without it, syslog messages interrupt whatever you're typing mid-keystroke. Apply it to console and VTY.

Verify Your Baseline

R1# show version ! IOS version, uptime, model, serial # R1# show clock ! current time (sync this with NTP later) R1# show users ! who is logged in right now R1# show running-config | section line ! check line configs only

03 Interface Configuration

Interfaces are where the rubber meets the road. Every outage you'll troubleshoot eventually comes back to an interface state, an IP, or a duplex/speed mismatch. Know these commands cold.

Interface Naming Conventions

Cisco names interfaces by type and slot/port. Examples: GigabitEthernet0/0/1 = gigabit, slot 0, sub-slot 0, port 1. The shorthand gi0/0/1 works just as well. Common abbreviations: fa (FastEthernet), gi (Gigabit), te (TenGig), se (Serial), lo (Loopback), vlan (SVI).

The Most Common Interface Config

R1(config)# interface gi0/1 R1(config-if)# description Uplink to BR2-Core ! always document! R1(config-if)# ip address 10.0.1.1 255.255.255.0 R1(config-if)# no shutdown ! routers default to shutdown! R1(config-if)# exit

The description field shows up in show interfaces outputs and in your monitoring system. When a coworker is troubleshooting at 2am and sees "Uplink to BR2-Core" instead of an unlabeled port, that's saving real money and time.

Speed, Duplex & Auto-Negotiation

R1(config-if)# speed 1000 ! force 1 Gbps (10, 100, 1000, or auto) R1(config-if)# duplex full ! full, half, or auto R1(config-if)# mdix auto ! auto-detect crossover vs straight-through
The classic duplex mismatch: one side hardcoded to full, the other left at auto. Auto can't negotiate properly with a hardcoded peer, so it falls back to half. Result: late collisions, high error counters, terrible performance, link still up. Rule: either hardcode both sides or auto-negotiate on both sides. Never mix.

Switchport Modes (Layer 2)

SW(config-if)# switchport mode access ! single VLAN, end device SW(config-if)# switchport access vlan 10 SW(config-if)# switchport mode trunk ! carries multiple VLANs SW(config-if)# switchport trunk allowed vlan 10,20,30 SW(config-if)# spanning-tree portfast ! skip listening/learning on access ports SW(config-if)# spanning-tree bpduguard enable ! shut port if a BPDU appears

Verifying Interfaces — the Go-To Commands

R1# show ip interface brief ! the #1 daily-driver command R1# show interfaces ! full details — errors, duplex, etc. R1# show interfaces gi0/1 ! one interface R1# show interfaces status ! switches: condensed port table R1# show interfaces description ! quickly find that one port R1# show interfaces counters errors ! who is dropping packets?

Reading show ip interface brief

StatusProtocolMeaning

Counter interpretation: in show interfaces, input errors with CRCs = bad cable / EMI / duplex mismatch. Late collisions = duplex mismatch (full vs half) or cable too long. Runts/giants = malformed frames. A handful is normal over months; if counters climb during your test, you've got a problem.

04 VLANs & Trunking

A switch with no VLANs is one big flat broadcast domain — every broadcast (ARP, DHCP, etc.) hits every port. VLANs are how we logically slice a switch into multiple broadcast domains so finance traffic doesn't see engineering traffic and a broadcast storm in one VLAN doesn't take everyone down.

Key Concepts

  • A VLAN = a Layer 2 broadcast domain. By default everyone is in VLAN 1.
  • An access port belongs to one VLAN. Frames leave it untagged. End devices plug into access ports.
  • A trunk port carries traffic for many VLANs between switches. Frames are tagged with a 4-byte 802.1Q header so the receiver knows which VLAN each frame belongs to.
  • The native VLAN on a trunk is the one VLAN whose frames are sent untagged. Default is VLAN 1. Must match on both ends.

Creating & Assigning VLANs

SW(config)# vlan 10 SW(config-vlan)# name SALES SW(config-vlan)# exit SW(config)# vlan 20 SW(config-vlan)# name ENGINEERING SW(config-vlan)# exit SW(config)# interface range fa0/1 - 12 ! configure many ports at once SW(config-if-range)# switchport mode access SW(config-if-range)# switchport access vlan 10
RANGE TIPinterface range saves enormous time. interface range fa0/1 - 24, gi0/1 - 2 grabs everything in one shot. Use it for bulk PortFast, BPDU Guard, VLAN assignment, etc.

Configuring a Trunk

SW(config)# interface gi0/24 SW(config-if)# switchport mode trunk SW(config-if)# switchport trunk encapsulation dot1q ! some IOS need this first SW(config-if)# switchport trunk native vlan 99 ! security best practice SW(config-if)# switchport trunk allowed vlan 10,20,30 ! limit which VLANs cross SW(config-if)# switchport nonegotiate ! disable DTP

Changing the native VLAN to an unused one (and not VLAN 1) defeats a class of attack called VLAN double-tagging. Pruning the allowed VLAN list means a broadcast storm in VLAN 50 doesn't traverse a trunk that doesn't need it. Real defense-in-depth.

DTP — Dynamic Trunking Protocol

DTP auto-negotiates trunks between Cisco switches. Useful for lab convenience, dangerous in production — an attacker plugging a laptop into an access port can negotiate a trunk and access every VLAN. Disable DTP on user-facing ports with switchport nonegotiate.

ModeBehavior
accessHardcoded access; will not form trunk
trunkHardcoded trunk; still sends DTP unless nonegotiate
dynamic desirableActively asks to form a trunk
dynamic autoWill trunk if asked but won't initiate

Verification

SW# show vlan brief ! VLAN table + assigned ports SW# show interfaces trunk ! trunks, allowed VLANs, native VLAN SW# show interfaces gi0/1 switchport ! per-port detail
VLAN troubleshooting checklist: Two hosts in the same VLAN on different switches can't ping each other? Check (1) the trunk is up, (2) the VLAN exists on both switches, (3) the VLAN is in the trunk's allowed list. All three must be true.

Voice VLANs

Cisco IP phones need their own VLAN but also pass-through data for the PC plugged into them. The phone tags voice traffic; the PC traffic stays untagged.

SW(config-if)# switchport mode access SW(config-if)# switchport access vlan 10 ! data VLAN for the PC SW(config-if)# switchport voice vlan 110 ! voice VLAN for the phone

05 Inter-VLAN Routing

VLANs isolate broadcast domains, which is great for security but bad if Sales does need to print to a printer in Engineering. The traffic has to leave Layer 2 and be routed between VLANs. Three ways to do this.

Method 1: Router-on-a-Stick

A single router link to the switch is configured as a trunk. The router has subinterfaces, one per VLAN, each with its own IP — that IP becomes the default gateway for hosts in that VLAN.

SW(config)# interface gi0/24 SW(config-if)# switchport mode trunk SW(config-if)# switchport trunk allowed vlan 10,20 R(config)# interface gi0/0 R(config-if)# no shutdown ! parent interface must be up R(config)# interface gi0/0.10 ! subinterface for VLAN 10 R(config-subif)# encapsulation dot1q 10 R(config-subif)# ip address 192.168.10.1 255.255.255.0 R(config)# interface gi0/0.20 R(config-subif)# encapsulation dot1q 20 R(config-subif)# ip address 192.168.20.1 255.255.255.0
Easy to forget: the parent interface (gi0/0) needs no shutdown — subinterfaces inherit its state. If the parent is shut, none of the subinterfaces work.

Method 2: Layer 3 Switch with SVIs

The faster, scalable approach. Modern campus networks use this almost universally. A Layer 3 switch can do routing in hardware (ASICs) — far faster than a router CPU.

SW(config)# ip routing ! enable L3 functionality SW(config)# interface vlan 10 ! SVI = Switch Virtual Interface SW(config-if)# ip address 192.168.10.1 255.255.255.0 SW(config-if)# no shutdown SW(config)# interface vlan 20 SW(config-if)# ip address 192.168.20.1 255.255.255.0 SW(config-if)# no shutdown

An SVI comes up only when (1) the VLAN exists on the switch and (2) at least one access port in that VLAN is up or a trunk carries it. Otherwise the SVI shows "up/down." This is the #1 SVI gotcha.

Method 3: Routed Ports on a Layer 3 Switch

Convert a switch port into a pure routed port (like a router interface).

SW(config-if)# no switchport ! becomes a routed port SW(config-if)# ip address 10.0.0.1 255.255.255.252

06 Spanning Tree Protocol

Ethernet has no Time-To-Live field. A broadcast frame on a Layer 2 loop circles forever and multiplies — within seconds you get a broadcast storm that takes down the whole network. STP exists to detect and block redundant paths automatically, leaving only loop-free paths active.

How STP Builds a Loop-Free Topology

  1. Elect the Root Bridge. The switch with the lowest Bridge ID (priority + MAC) wins. Default priority is 32768 — so the switch with the oldest (lowest) MAC tends to win by accident. You should choose your root deliberately.
  2. Each non-root switch picks one Root Port. The port with the lowest cumulative cost back to the root.
  3. Each segment picks one Designated Port. The single port on a segment that advertises the lowest cost.
  4. Remaining ports are blocked. They still receive BPDUs but discard everything else — breaking the loop.

Classic STP convergence is 30–50 seconds. Rapid STP (RSTP / 802.1w) reduces this to a few seconds and is the default on modern Cisco switches as Rapid PVST+.

Setting the Root Bridge Deliberately

SW(config)# spanning-tree vlan 1-100 root primary ! macro: priority 24576 SW(config)# spanning-tree vlan 1-100 root secondary ! priority 28672 (backup root) SW(config)# spanning-tree vlan 10 priority 4096 ! manual (must be multiple of 4096) SW(config)# spanning-tree mode rapid-pvst ! use RSTP per VLAN

Always pick your root manually. The default behavior elects whichever switch has the lowest MAC — usually the oldest, slowest, most beat-up switch in the closet. You want your core / distribution switch to be root because that's where traffic naturally converges.

PortFast & BPDU Guard — The Edge-Port Combo

SW(config-if)# spanning-tree portfast ! skip listening/learning, go to forwarding SW(config-if)# spanning-tree bpduguard enable ! shut port if a BPDU shows up SW(config)# spanning-tree portfast default ! globally enable on all access ports SW(config)# spanning-tree portfast bpduguard default ! globally enable BPDU Guard with PortFast

PortFast lets an access port skip the 30-second STP wait and go straight to forwarding — DHCP requests succeed, Windows doesn't time out. BPDU Guard protects you: if someone plugs a rogue switch into a PortFast port, BPDUs will arrive and BPDU Guard err-disables the port instantly.

Never enable PortFast on a switch-to-switch link. You'll create a temporary loop during convergence. PortFast is only for end devices.

Root Guard

Prevents a connected switch from becoming root. Apply on ports facing switches you don't control — partner connections, customer ports. If a superior BPDU arrives, the port goes into a root-inconsistent blocking state until BPDUs stop.

SW(config-if)# spanning-tree guard root

Verification

SW# show spanning-tree ! per-VLAN root, your role, port states SW# show spanning-tree vlan 10 SW# show spanning-tree summary ! mode, root by VLAN, features SW# show spanning-tree interface gi0/1 detail

07 EtherChannel

EtherChannel bundles 2–8 physical links into one logical link (the "Port-Channel"). Benefits: aggregated bandwidth, automatic failover if a member dies, and STP sees the bundle as one link — so you don't lose half your capacity to blocking.

Negotiation Protocols

ProtocolTypeActive/Init ModePassive Mode
LACP (802.3ad)Open standardactivepassive
PAgPCisco proprietarydesirableauto
StaticNoneonon

Forming rules: at least one side must initiate. LACP needs active on at least one side; PAgP needs desirable. on / on works (static). auto / auto never forms. Never mix protocols — LACP and PAgP can't talk to each other.

Configuration

SW(config)# interface range gi0/1 - 2 SW(config-if-range)# channel-group 1 mode active ! creates Po1, uses LACP SW(config)# interface port-channel 1 SW(config-if)# switchport mode trunk ! configure logical interface SW(config-if)# switchport trunk allowed vlan 10,20,30
Consistency is mandatory. All bundle members must match: speed, duplex, switchport mode, allowed VLAN list, native VLAN. A mismatch on any of these = the channel won't form, or it forms partially. Configure the Port-Channel interface for trunking; the bundle inherits to members.

Verification

SW# show etherchannel summary ! the daily-driver command SW# show etherchannel port-channel SW# show interfaces port-channel 1

In show etherchannel summary, look for the flags after the Po name: SU = "Layer 2, in use" — what you want. P next to a port = it's bundled and in use. I = stand-alone (didn't bundle).

08 Routing Fundamentals

A router's job is simple: receive a packet, look at the destination IP, decide where to send it, and forward. The "deciding" part is what we call routing, and it's driven by the routing table.

How a Router Decides — Three Tiebreakers, In Order

  1. Longest prefix match — if multiple routes match the destination, the most specific (longest mask) wins. A /30 beats a /24 every time, no matter the source.
  2. Administrative Distance (AD) — if same prefix length, the router prefers the route source with the lowest AD. AD is a measure of trust in the route source.
  3. Metric — if AD ties (same routing protocol giving two paths), the lowest metric wins. Metric is protocol-specific (OSPF cost, EIGRP composite, etc.).

Administrative Distance Values

SourceADWhy
Connected0Directly attached — the router knows for sure

eBGP20External BGP — generally inter-AS
EIGRP (internal)90Cisco's advanced distance-vector protocol
OSPF110Link-state, fast, open standard
RIPv2120Old distance-vector, hop-count metric

Reading the Routing Table

R1# show ip route Codes: C - connected, S - static, R - RIP, O - OSPF, D - EIGRP, B - BGP C 10.0.0.0/24 is directly connected, GigabitEthernet0/0 S 192.168.5.0/24 [1/0] via 10.0.0.2 O 172.16.10.0/24 [110/2] via 10.0.0.2, GigabitEthernet0/0 S* 0.0.0.0/0 [1/0] via 10.0.0.1 ! gateway of last resort

Inside the brackets [110/2]: the first number is AD (110 = OSPF), the second is the metric (cost 2). The S* means it's the candidate default route.

Key show Commands

R1# show ip route ! full table R1# show ip route 192.168.5.55 ! which route matches this IP? R1# show ip route ospf ! only OSPF-learned routes R1# show ip route connected ! directly connected only R1# show ip protocols ! what protocols, what networks, timers R1# show ip cef ! CEF table — actual forwarding info

show ip route X.X.X.X is a lifesaver. Instead of scanning a 500-line routing table for the most specific match, the router tells you exactly which route it would use. Master this command.

09 Static Routing

A static route is one you type in. They're simple, predictable, and add zero CPU overhead — but they don't react to topology changes. Use them for: stub networks, default routes, and as floating backups.

The Four Ways to Specify a Static Route

R1(config)# ip route 192.168.5.0 255.255.255.0 10.0.0.2 ! next-hop IP (most common) R1(config)# ip route 192.168.5.0 255.255.255.0 gi0/0 ! exit interface only R1(config)# ip route 192.168.5.0 255.255.255.0 gi0/0 10.0.0.2 ! fully specified R1(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.1 ! default route
FormProsCons
Next-hop onlySurvives interface re-numberingRequires recursive lookup
Exit interface onlyNo recursive lookupOn multi-access links, router ARPs for every destination — wasteful
Fully specifiedBest of both — no ARP issues, explicitSlightly more typing

Default Route — the One You'll Use Most

A default route matches anything not in the table. On a branch router pointed at the corporate office, this is usually all you need — one default plus a routing protocol back to corp.

Floating Static Routes — Manual Failover

Add an artificial AD higher than your primary protocol's AD. The router prefers the protocol-learned route; if that disappears, the floating static takes over.

R1(config)# ip route 192.168.5.0 255.255.255.0 10.0.0.2 ! AD 1 — preferred R1(config)# ip route 192.168.5.0 255.255.255.0 10.0.99.2 150 ! AD 150 — backup

Floating statics are the cleanest way to do primary/backup WAN failover. Primary = OSPF route (AD 110). Backup = static with AD 150 over the secondary ISP. OSPF dies → static kicks in seconds later.

IPv6 Static Routes

R1(config)# ipv6 unicast-routing R1(config)# ipv6 route 2001:db8:5::/64 2001:db8:0::2 R1(config)# ipv6 route ::/0 2001:db8:0::1 ! default route in v6

10 OSPF — Open Shortest Path First

OSPF is the routing protocol the CCNA tests heaviest. It's a link-state IGP — every router floods info about its directly connected links, every router builds an identical map (the LSDB), and each independently runs Dijkstra's algorithm to calculate the shortest path. The CCNA covers single-area OSPFv2.

How OSPF Forms a Neighbor Relationship

  1. OSPF sends Hello packets every 10 seconds (broadcast network) to multicast 224.0.0.5.
  2. If a neighbor's Hello matches on the required parameters, they advance through states: Down → Init → 2-Way → ExStart → Exchange → Loading → Full.
  3. Once Full, they exchange LSAs and have identical topology databases.

Parameters That MUST Match for Adjacency

  • Area number
  • Hello and Dead timers (10/40 by default on broadcast)
  • Subnet mask & subnet (must be on the same IP subnet)
  • Authentication (if used, same type and key)
  • MTU (Cisco-specific check — both sides must agree)
  • Stub area flag (both must have the same area type)
The classic "stuck in EXSTART/EXCHANGE" symptom = MTU mismatch. If you see this, check interface MTUs on both ends — they must match. As a workaround, ip ospf mtu-ignore on the interface disables the check.

Router ID — How OSPF Identifies Itself

Selected in this order: (1) router-id command (manual); (2) highest loopback IP at OSPF start time; (3) highest active interface IP. The Router ID is set once when OSPF starts — change it and you need to clear ip ospf process for it to take effect.

Configuration — Two Ways

! Method 1: classic network statement R1(config)# router ospf 1 ! "1" is process ID, locally significant R1(config-router)# router-id 1.1.1.1 R1(config-router)# network 10.0.0.0 0.0.0.255 area 0 ! wildcard mask = inverse subnet mask R1(config-router)# passive-interface gi0/2 ! don't send Hellos on this interface R1(config-router)# default-information originate ! advertise the default route to peers ! Method 2: per-interface (modern, cleaner) R1(config-if)# ip ospf 1 area 0

DR/BDR Election on Multi-Access Networks

On a broadcast network (Ethernet), OSPF would have every router form a full mesh — N*(N-1)/2 adjacencies. Instead it elects a Designated Router (DR) and Backup DR (BDR). All other routers form a full adjacency only with the DR/BDR, drastically reducing LSA flooding.

  • Highest interface priority wins (default 1; priority 0 = never DR/BDR).
  • Tie → highest Router ID.
  • Election is non-preemptive — a new high-priority router doesn't kick out the existing DR.
R1(config-if)# ip ospf priority 100 ! make this router prefer being DR R1(config-if)# ip ospf priority 0 ! never become DR (good for stub routers)

OSPF Cost — the Metric

Cost = reference bandwidth ÷ interface bandwidth. Default reference bandwidth is 100 Mbps. That means anything 100 Mbps or faster has cost 1 by default — which makes 1 Gbps and 10 Gbps look identical. Fix this with:

R1(config-router)# auto-cost reference-bandwidth 10000 ! reference = 10 Gbps R1(config-if)# ip ospf cost 25 ! or set it manually

Always set the reference bandwidth to match or exceed the fastest link in your network — and set it the same on every router. Otherwise OSPF picks dumb paths through slow links.

Passive Interfaces

Stops a router from sending Hellos out an interface (still advertises the subnet, just doesn't try to form a neighbor relationship). Always make user-facing LAN interfaces passive — they don't have OSPF neighbors, and you don't want OSPF Hellos leaking out where a malicious user could see them and inject routes.

R1(config-router)# passive-interface default ! all interfaces passive by default R1(config-router)# no passive-interface gi0/0 ! except the ones facing peers

Verification

R1# show ip ospf neighbor ! who am I peered with? R1# show ip ospf interface gi0/0 ! cost, timers, state, area R1# show ip ospf interface brief R1# show ip ospf database ! the LSDB R1# show ip protocols ! process ID, router ID, networks

11 First Hop Redundancy Protocols

A host has one default gateway. If that router dies, the host's traffic dies with it — unless the gateway is virtualized across multiple routers. That's what FHRPs do. Hosts point at a virtual IP; the real routers behind it negotiate which one is currently answering.

! R1 — primary R1(config-if)# ip address 192.168.10.2 255.255.255.0 R1(config-if)# standby 1 ip 192.168.10.1 ! virtual IP (hosts' gateway) R1(config-if)# standby 1 priority 110 ! default is 100; higher wins R1(config-if)# standby 1 preempt ! take Active back when recovered R1(config-if)# standby 1 authentication md5 key-string ourkey ! R2 — backup, default priority 100, becomes Standby R2(config-if)# ip address 192.168.10.3 255.255.255.0 R2(config-if)# standby 1 ip 192.168.10.1 R2(config-if)# standby 1 preempt

The virtual IP must be in the same subnet as the real interfaces and cannot equal any real interface IP. HSRP uses virtual MAC 0000.0c07.acXX where XX is the group number in hex.

Forgetting preempt is a classic mistake. Without it, even if R1 (higher priority) comes back online, R2 stays Active forever. Always configure preempt on the router you want to be Active.

Interface Tracking — Smarter Failover

What if R1 is up but its uplink to the core is down? You want R1 to surrender Active to R2. Tracking does this — decrement the priority if a tracked interface goes down.

R1(config)# track 1 interface gi0/2 line-protocol R1(config-if)# standby 1 track 1 decrement 20

If gi0/2 goes down, priority drops from 110 to 90 → R2 (still at 100) preempts → traffic fails over even though R1 itself is "up." Smart.

Verification

R1# show standby ! state, virtual IP/MAC, peer, timers R1# show standby brief ! one-line per group

12 DHCP

Hosts need: an IP, a mask, a default gateway, and DNS servers. DHCP delivers all four (and more) automatically. Without DHCP, you'd be statically configuring every laptop, phone, and printer by hand.

The DORA Process — Detailed

  1. Discover — client (no IP yet) broadcasts a DHCPDISCOVER to 255.255.255.255. UDP source 68 → dest 67.
  2. Offer — server replies (unicast or broadcast) with DHCPOFFER containing a proposed IP and lease info.
  3. Request — client broadcasts DHCPREQUEST formally requesting that offer (broadcast so any other servers know their offer was passed over).
  4. Acknowledge — server replies with DHCPACK confirming the lease.

After half the lease expires, the client tries to renew (unicast directly to the server). If renewal fails, it tries again at 87.5% (rebinding, broadcast). After lease expiration with no renewal, it must DORA from scratch.

Cisco Router as DHCP Server

R1(config)# ip dhcp excluded-address 192.168.10.1 192.168.10.10 ! reserve for static / infra R1(config)# ip dhcp pool USERS R1(dhcp-config)# network 192.168.10.0 255.255.255.0 R1(dhcp-config)# default-router 192.168.10.1 R1(dhcp-config)# dns-server 8.8.8.8 1.1.1.1 R1(dhcp-config)# domain-name corp.local R1(dhcp-config)# lease 7 ! 7-day lease

You must exclude addresses you've used for static assignments — router interfaces, printers, servers. Otherwise DHCP will happily hand someone else's static IP to a laptop, and you'll get a duplicate IP outage that's miserable to diagnose.

DHCP Relay (ip helper-address)

A real network has the DHCP server in a data center — not in every branch closet. But DHCP Discover is a broadcast, and routers don't forward broadcasts. The fix: ip helper-address on the router interface facing the clients. The router catches the broadcast, rewrites it as a unicast to your DHCP server, and forwards it.

R1(config)# interface gi0/0 ! the LAN-facing interface R1(config-if)# ip helper-address 10.50.0.10

Cisco Switch as DHCP Client

Sometimes you want a switch's management IP to come from DHCP.

SW(config)# interface vlan 1 SW(config-if)# ip address dhcp SW(config-if)# no shutdown

Verification

R1# show ip dhcp binding ! who has what lease R1# show ip dhcp pool ! addresses in use vs available R1# show ip dhcp conflict ! duplicate IPs detected R1# debug ip dhcp server packet ! watch DORA happen live

13 NAT & PAT

NAT translates private IPs to public ones. Two big reasons it exists: (1) IPv4 address exhaustion — millions of hosts behind one public IP, and (2) hides internal addressing from the outside.

NAT Address Terminology — Memorize

TermWhose IP?Where seen from?
Inside LocalInside hostFrom the inside (the real private IP)
Inside GlobalInside hostFrom the outside (the public IP it appears as)
Outside GlobalOutside hostFrom the outside (its real public IP)
Outside LocalOutside hostFrom the inside (rarely different from global)

Mnemonic: local = where the address actually lives, global = how it's seen on the public internet. Inside vs outside = which side of NAT the host is on.

Static NAT — 1:1 Fixed Mapping

Use case: making an internal server reachable from the internet on a fixed public IP.

R1(config)# ip nat inside source static 192.168.1.10 203.0.113.10 R1(config)# interface gi0/0 R1(config-if)# ip nat inside R1(config)# interface gi0/1 R1(config-if)# ip nat outside

Dynamic NAT — Pool of Public IPs

Inside hosts get translated to one of N public IPs from a pool. Rare today (still uses too many publics) but you should know it.

R1(config)# ip nat pool MYPOOL 203.0.113.10 203.0.113.20 netmask 255.255.255.0 R1(config)# access-list 1 permit 192.168.1.0 0.0.0.255 R1(config)# ip nat inside source list 1 pool MYPOOL

PAT (NAT Overload) — the Universal Choice

Many private hosts share one public IP, distinguished by source port. This is what every home router does, what every business edge does — virtually all NAT in the world is PAT.

R1(config)# access-list 1 permit 192.168.1.0 0.0.0.255 R1(config)# ip nat inside source list 1 interface gi0/1 overload R1(config)# interface gi0/0 R1(config-if)# ip nat inside R1(config)# interface gi0/1 R1(config-if)# ip nat outside

The overload keyword is the only thing that turns NAT into PAT. Forget it and you have a one-IP dynamic pool that only one host can use at a time. Everyone else gets dropped.

Verification & Troubleshooting

R1# show ip nat translations ! every active translation R1# show ip nat statistics ! totals, hits, misses R1# debug ip nat ! see translations as they happen (verbose!) R1# clear ip nat translation * ! wipe NAT table (forces re-creation)

14 NTP, DNS, Syslog, SNMP

NTP — Network Time Protocol

Accurate clocks aren't optional. If two devices disagree on the time, log correlation during an outage becomes impossible, and certificate validation breaks. NTP uses UDP 123 and a hierarchy of strata — stratum 1 = atomic clock; each hop up is +1 stratum.

R1(config)# ntp server 0.pool.ntp.org R1(config)# ntp server 192.168.1.1 ! internal NTP source R1(config)# clock timezone PST -8 ! configure local timezone R1(config)# clock summer-time PDT recurring ! DST R1# show ntp associations ! who am I peering with? R1# show ntp status ! am I synchronized? R1# show clock ! what time do I think it is?

DNS Resolution on a Device

R1(config)# ip name-server 8.8.8.8 1.1.1.1 R1(config)# ip domain-lookup ! enable DNS lookups (on by default) R1(config)# ip domain-name corp.local R1(config)# no ip domain-lookup ! prevent typos from triggering DNS hangs
CLASSIC ANNOYANCEMistype a command in EXEC mode and the router tries to DNS-resolve it as a hostname, hanging your session for 30 seconds. Always run no ip domain-lookup on devices that don't need DNS.

Syslog — Logging

The single most important thing for troubleshooting: every device should send logs to a central server.

R1(config)# logging host 10.50.0.20 ! syslog server IP R1(config)# logging trap informational ! severity 6 and lower (more severe) R1(config)# logging buffered 16384 ! 16KB local log buffer R1(config)# service timestamps log datetime msec localtime show-timezone R1# show logging ! local log buffer

SNMP — Monitoring

SNMP lets a Network Management System (Nagios, PRTG, SolarWinds, etc.) poll your devices for stats and receive traps.

! SNMPv2c — community-string based (use only on trusted networks) R1(config)# snmp-server community ROCorp RO ! read-only community R1(config)# snmp-server host 10.50.0.30 ROCorp R1(config)# snmp-server contact netadmin@corp.local R1(config)# snmp-server location DC1-Rack-7 ! SNMPv3 — adds authentication and encryption R1(config)# snmp-server group ADMINS v3 priv R1(config)# snmp-server user netmon ADMINS v3 auth sha SecretAuth priv aes 128 SecretPriv
🔒
Real-world security: SNMPv2c sends community strings in clear text. Anyone sniffing your network can read them. Always use SNMPv3 with authPriv (auth + encryption) for any device outside a fully trusted segment.

16 SSH & AAA

SSH — Always Replace Telnet

Telnet sends everything (including passwords) in plain text. SSH encrypts the whole session. No legitimate reason to use Telnet on production.

R1(config)# hostname R1 R1(config)# ip domain-name corp.local ! required for key generation R1(config)# username admin secret StrongPass1 R1(config)# crypto key generate rsa modulus 2048 ! 2048+ bit key R1(config)# ip ssh version 2 ! SSHv2 only — v1 is insecure R1(config)# ip ssh time-out 60 ! login timeout in seconds R1(config)# ip ssh authentication-retries 3 R1(config)# line vty 0 15 R1(config-line)# transport input ssh R1(config-line)# login local
Pre-requisites for crypto key generation: hostname must not be default ("Router" or "Switch"), and an IP domain name must be set. Without both, crypto key generate rsa fails.

AAA — Authentication, Authorization, Accounting

For more than ~10 devices, local user databases become unmanageable. AAA centralizes it — every device asks a RADIUS or TACACS+ server "is this user allowed?"

The keyword local at the end is your fallback. If the TACACS+ server is unreachable, the device falls back to local authentication — otherwise a server outage locks everyone out of every device. Always configure a fallback.

17 Access Control Lists

ACLs are ordered lists of permit and deny rules. The router walks them top-to-bottom, takes the action of the first match, and stops checking. There is an implicit deny any at the end of every ACL — anything not explicitly permitted is dropped.

ACL Types

TypeNumber RangeMatches On
Standard numbered1–99, 1300–1999Source IP only
Extended numbered100–199, 2000–2699Source IP, dest IP, protocol, ports, flags
Standard namedany nameSource IP only
Extended namedany nameEverything extended numbered does

Placement Rules — Critical for the Exam

  • Standard ACL → place as close to the destination as possible. Reason: a standard ACL only sees source IP, so placing it close to source might block traffic to legitimate destinations.
  • Extended ACL → place as close to the source as possible. Reason: drop unwanted traffic immediately, before it eats bandwidth across your network.

Standard ACL — Block a Subnet

R1(config)# access-list 10 deny 192.168.50.0 0.0.0.255 R1(config)# access-list 10 permit any R1(config)# interface gi0/1 R1(config-if)# ip access-group 10 out
The number-one ACL mistake: writing only deny statements. Because of the implicit deny any, an ACL like "deny X" then nothing else blocks everything. Always end with an explicit permit for traffic you want to allow.

Extended ACL — Real-World Example

Allow inside users to browse the web; allow them to ping; block everything else inbound from the internet (except established sessions).

R1(config)# ip access-list extended FROM-INTERNET R1(config-ext-nacl)# permit tcp any any established ! return traffic for our sessions R1(config-ext-nacl)# permit icmp any any echo-reply ! allow ping replies R1(config-ext-nacl)# permit tcp any host 203.0.113.10 eq 443 ! external can reach web server R1(config-ext-nacl)# deny ip any any log ! log denies for visibility R1(config)# interface gi0/1 R1(config-if)# ip access-group FROM-INTERNET in

The established Keyword — Underrated

Matches TCP segments with ACK or RST flag set — i.e. anything that's part of an existing session (not a fresh SYN). Lets you permit replies to your users' outbound connections without permitting new inbound connections. Stateless but useful.

Wildcard Mask Shortcuts

You WantUse
One specific hosthost 10.1.1.1 (= 10.1.1.1 0.0.0.0)
Any hostany (= 0.0.0.0 255.255.255.255)
A /24 subnet10.1.1.0 0.0.0.255
A /16 subnet10.1.0.0 0.0.255.255

Editing Named ACLs — Use Sequence Numbers

Numbered ACLs are append-only — you can't insert into the middle. Named ACLs let you use sequence numbers to insert lines anywhere.

R1(config)# ip access-list extended FROM-INTERNET R1(config-ext-nacl)# 15 permit tcp any host 203.0.113.20 eq 25 ! insert line 15 R1(config-ext-nacl)# no 30 ! delete line 30 R1# show access-lists ! see numbered lines + hit counts R1# show ip access-lists FROM-INTERNET R1# show ip interface gi0/1 | include access ! verify what's applied
📊
Hit counters tell a story. show access-lists shows how many packets matched each line. Zero hits on a line for weeks = either nobody is generating that traffic, or the order is wrong and an earlier line is catching it first.

18 Layer 2 Security

Most security focuses on Layer 3/4, but Layer 2 attacks (right at the switch port) can bypass everything above. These three features lock it down: Port Security, DHCP Snooping, Dynamic ARP Inspection.

Port Security

Limits which and how many MAC addresses can use a switch port. Stops MAC flooding, rogue switches, and someone unplugging the receptionist's PC to plug in their own laptop.

SW(config-if)# switchport mode access ! port-security requires access mode SW(config-if)# switchport port-security SW(config-if)# switchport port-security maximum 2 ! allow up to 2 MACs (PC + phone) SW(config-if)# switchport port-security mac-address sticky ! learn dynamically, save to config SW(config-if)# switchport port-security violation shutdown ! action on violation SW(config-if)# switchport port-security aging time 60 ! optional: expire learned MACs

Violation Modes

ModeDrops?Logs?Counter?Disables Port?
protectYesNoNoNo
restrictYesYes (syslog/SNMP)YesNo
shutdown (default)YesYesYesYes (err-disable)

If a port goes err-disabled: shutdown then no shutdown on the interface to re-enable. Or configure auto-recovery:

SW(config)# errdisable recovery cause psecure-violation SW(config)# errdisable recovery interval 300 ! auto-recover after 5 min

DHCP Snooping

Rogue DHCP servers (intentional or accidental — somebody's home router plugged in) hand out wrong gateways and DNS. DHCP Snooping classifies ports as trusted (uplinks to your DHCP server) or untrusted (everything else). DHCPOFFER packets are dropped on untrusted ports.

SW(config)# ip dhcp snooping SW(config)# ip dhcp snooping vlan 10,20,30 SW(config)# interface gi0/24 ! uplink to DHCP server SW(config-if)# ip dhcp snooping trust

Dynamic ARP Inspection (DAI)

Validates every ARP packet against the DHCP Snooping binding table. Stops ARP-poisoning man-in-the-middle attacks. Requires DHCP Snooping to be configured first.

SW(config)# ip arp inspection vlan 10,20,30 SW(config-if)# ip arp inspection trust ! on uplinks/trunk

The L2 Security Stack — Why You Want All Three

Port Security stops MAC flooding and unauthorized devices. DHCP Snooping stops rogue DHCP servers from hijacking client config. DAI stops ARP poisoning, which is the most common gateway-MITM attack. Together they make a switch actually defensible at Layer 2 — and they're all free features.

19 Troubleshooting Methodology

A good admin doesn't guess. They follow a method. Work from Layer 1 up, or from Layer 7 down — but always systematically.

The Layered Approach (Bottom Up)

  1. Layer 1 — Physical: Cable plugged in? Link light? Other end up? Right cable type? Use show interface gi0/1 — if status is "down/down," it's L1.
  2. Layer 2 — Data Link: Right VLAN? Trunk allowing the VLAN? Same encapsulation both sides? Native VLAN matches? Use show vlan brief, show interfaces trunk.
  3. Layer 3 — Network: IP/mask correct? Default gateway right? Routing table has a path? ACL blocking? Use show ip route X.X.X.X, ping, traceroute.
  4. Layer 4 — Transport: Is the port open? Firewall in the path? Use telnet x.x.x.x 80 to test TCP reachability (irony noted).
  5. Layer 7 — Application: DNS resolving? Service running? Wrong URL? Check the app itself.

ping — Interpret the Output

R1# ping 8.8.8.8 Sending 5, 100-byte ICMP Echos to 8.8.8.8: !!!!! ! all succeeded ..... ! all timed out — no reply U.U.U ! Unreachable from a router along the way .!!.! ! partial loss — investigate further
CharMeaning
!Success (echo reply received)

UDestination unreachable (ICMP unreachable from a router)
QSource quench (congestion)
MCould not fragment

Extended Ping — Source from an Interface

Default ping uses the exit interface's IP as source. Sometimes you want to ping from a specific interface to verify return routing for that subnet.

R1# ping Protocol [ip]: Target IP address: 8.8.8.8 Repeat count [5]: 100 Datagram size [100]: 1500 Source address or interface: gi0/0 Type escape sequence to abort. ...

traceroute

Shows the path packets take by manipulating TTL. Each hop sends back an ICMP TTL-exceeded. Where it stops responding = where the problem starts.

R1# traceroute 8.8.8.8 1 10.0.0.1 4 ms 2 192.168.1.1 8 ms 3 * * * ! something blocked here — firewall? Wrong route? 4 8.8.8.8 22 ms

The Daily-Driver Show Commands

R1# show ip interface brief ! interface status at a glance R1# show ip route ! routing table R1# show cdp neighbors detail ! what's on the other end of each port R1# show mac address-table ! switches: where is MAC X? R1# show arp ! IP-to-MAC bindings this router knows R1# show logging ! recent log messages R1# show version ! IOS, uptime, model R1# show processes cpu sorted | exclude 0.00 ! what's eating CPU? R1# show memory summary ! memory usage

Debug — Power Tool, Treat With Respect

Debug commands can crash a production router. They generate massive CPU and console traffic. Use them sparingly, never on a busy device without thinking, and always have undebug all ready.

R1# debug ip ospf events R1# debug ip dhcp server packet R1# undebug all ! "u all" — turn off ALL debug R1# show debugging ! what debugs are currently on?

20 Network Admin Best Practices

The exam doesn't test these directly, but they separate a junior admin from someone who can run a network. Adopt these habits from day one.

Documentation Is Non-Negotiable

  • Network diagrams — physical + logical. Update them when anything changes.
  • IP address management (IPAM) — at minimum a spreadsheet, ideally a tool like phpIPAM or NetBox. Reserve a /24 → it's used → mark it used.
  • VLAN database — which VLAN is for what, what subnet, where it lives, who owns it.
  • Cabling records — which switch port connects to which patch panel, which goes to which wall jack.
  • Device inventory — model, serial, location, IOS version, maintenance contract.

Change Management

  1. Document what you're going to change before you do it.
  2. Have a back-out plan. "If this breaks at step 4, here is how I revert."
  3. Save the current config before changing: copy running-config flash:pre-change-2026-05-27.
  4. Make the change during a maintenance window if possible.
  5. Verify the change. Then verify it worked end-to-end (don't just verify the device — verify the user's actual experience).
  6. Save the new config: wr. Update documentation.

Saving Yourself: reload in

About to make a risky change remotely? Schedule a reboot in 10 minutes before you start. If you lock yourself out, the reboot reloads the last saved config and you're back in.

R1# reload in 10 ! reload in 10 minutes R1# ! ... make your changes ... R1# ! ... verify they work ... R1# reload cancel ! if all is good, cancel the reload R1# wr ! save

Every senior network admin has a story of locking themselves out of a remote device. The ones who lived to tell it had reload in running. This single habit will save your job at some point.

Naming & IP Conventions

  • Hostnames: SITE-FUNCTION-NUMBER, e.g. NYC-CORE-01, LAX-DIST-02. Consistent across the company.
  • Interface descriptions: what's on the other end. To: LAX-CORE-01 gi0/24.
  • Subnetting: reserve ranges by purpose. e.g. /24 per VLAN, even numbers = data, odd = voice. Whatever you pick, be consistent.

Backup Configs

Every config should be backed up off the device. TFTP/SFTP to a server, version-controlled in Git, or via a tool like RANCID/Oxidized that pulls daily.

R1# copy running-config tftp: R1# copy running-config scp://user@10.50.0.50/configs/R1.cfg

Monitor Proactively

  • Syslog → central server, with alerting on severity ≤ 4 (Warning and worse).
  • SNMP polling for interface utilization, errors, CPU, memory, environment (temp, power, fans).
  • NetFlow / sFlow for traffic visibility — what protocols, who's talking to whom.
  • Synthetic monitoring — actually ping/curl from a probe to detect outages before users do.

The Mindset

Two skills separate good admins from great ones:

  1. Lab everything first. Free tools — Cisco Packet Tracer, GNS3, EVE-NG, CML — let you test changes in a virtual replica before touching production. Always lab. Always.
  2. Read the actual output, not what you expect. Your brain will fill in what it expects to see. Force yourself to read every line of show interface, every digit of an IP. Half of troubleshooting is just actually looking.
