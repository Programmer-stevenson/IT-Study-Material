DOMAIN 01

Cloud Concepts

25–30% of the exam · the "why cloud" foundations

No Azure specifics here — just the universal vocabulary of cloud computing. If you can match a scenario to the right model and service type, you own this domain.

What is cloud computing?

Delivering computing services — compute storage networking databases AI — over the internet, paying only for what you use.

  • CapEx — upfront capital expense; buy hardware you own and depreciate.
  • OpEx — ongoing operational expense; rent as a service, no upfront cost.
  • Consumption-based model — pay-as-you-go, scale with demand, never pay for idle capacity.

Shared Responsibility Model

Splits security duties between provider and customer. The split shifts with the service type.

  • Always the provider: physical datacenter, physical network, physical hosts.
  • Always the customer: your data, devices, and accounts/identities.
  • It depends: OS, network controls, apps — depends on IaaS / PaaS / SaaS.
Memory hookIaaS = you own the most. SaaS = the provider owns the most. Data & identities are always yours.

Cloud Deployment Models

ModelWhat it is
PublicProvider-owned, shared, over the internet. Low cost, high scale, no maintenance, less control.
PrivateDedicated to one org. More control & compliance, higher cost, you maintain it.
HybridCombines public + private. Flexibility, use existing infra, meet compliance while bursting to cloud.
Multi-cloudUsing more than one cloud provider.

Benefits of the Cloud

  • High availability — stays up despite failures (backed by SLAs).
  • Scalability — vertical (scale up/down: bigger VM) vs horizontal (scale out/in: more VMs).
  • Elasticity — auto add/remove resources to match live demand.
  • Reliability — recover from failures; distributed by design.
  • Predictability — performance (autoscale, load balancing) & cost (forecast, TCO).
  • Security & governance — policies, templates, patching, compliance.
  • Manageability — of the cloud (autoscale, templates) & in the cloud (portal, CLI, PowerShell, API).

Cloud Service Types — IaaS vs PaaS vs SaaS

TypeYou manageProvider managesBest for
IaaSOS, runtime, apps, dataPhysical infra, virtualizationLift-and-shift, test/dev, storage & backup — max control
PaaSApps, dataOS, runtime, infraBuilding & deploying apps, analytics/BI — no OS upkeep
SaaSYour data & accessEverything elseReady-to-use software like Microsoft 365 — least effort
Scenario trick"Rent a VM" = IaaS. "Deploy code without managing servers" = PaaS. "Just log in and use it" = SaaS.
DOMAIN 02

Azure Architecture & Services

35–40% of the exam · the biggest domain

The heaviest section. Know the resource hierarchy cold, and be able to pick the right compute, storage, network, and identity service for a scenario.

Core Architecture — the hierarchy

Top to bottom: Management groups → Subscriptions → Resource groups → Resources

  • Region — a geographic area with one or more networked datacenters. Some services/VM sizes are region-specific.
  • Region pairs — a region paired with another ≥300 miles away in the same geography for disaster recovery; updates roll out sequentially, recovery is prioritized.
  • Availability Zones — physically separate datacenters within one region (min. 3), each with independent power, cooling, network. Protect against a datacenter failure. Use zonal (pinned) or zone-redundant.
  • Sovereign regions — isolated clouds: Azure Government (US) and Azure China (operated by 21Vianet).
  • Resource — an instance of a service (a VM, a database, a storage account).
  • Resource group — a logical container; every resource lives in exactly one. Delete the group → delete everything in it. Apply access & policy here.
  • Subscription — a billing and access-control boundary linked to an account.
  • Management group — governs policy & access across many subscriptions at once.

Compute Services

OptionUse it when
Virtual MachinesYou need full OS control (IaaS).
VM Scale SetsAuto-scale a group of identical VMs.
Availability SetsSpread VMs across fault + update domains to avoid downtime.
Containers (ACI / AKS)Lightweight, portable microservices; AKS = managed Kubernetes.
Azure FunctionsServerless, event-driven, pay per execution.
App ServiceHost web apps / APIs without managing infra.
Azure Virtual DesktopCloud-hosted Windows desktops.

Networking Services

  • Virtual Network (VNet) — your private network in Azure.
  • Subnets — segment a VNet.
  • Peering — connect VNets together privately.
  • Azure DNS — host and resolve domains.
  • VPN Gateway — encrypted tunnel over the public internet (site-to-site, point-to-site).
  • ExpressRoute — a private, dedicated connection that bypasses the public internet.
Exam trapVPN Gateway = over the internet (encrypted). ExpressRoute = private circuit, not over the internet.

Storage Services

  • Blob — object storage for unstructured data (files, images, backups).
  • Files — managed file shares (SMB/NFS).
  • Queue — messaging between app components.
  • Table — NoSQL key-value store.
  • Disk — block storage for VMs.

Access tiers (blob):

TierFor data accessed…
HotFrequently. High storage cost, low access cost.
CoolInfrequently, stored ≥30 days.
ColdRarely, stored ≥90 days.
ArchiveAlmost never, ≥180 days. Cheapest storage, offline — must rehydrate.

Redundancy & Migration

  • LRS — 3 copies in one datacenter (cheapest).
  • ZRS — copies across availability zones in one region.
  • GRS — copies to a paired secondary region.
  • GZRS — zone-redundant + geo-redundant (highest durability).
  • RA- variants — add read access to the secondary region.

Moving data: AzCopy, Azure Storage Explorer, Azure File Sync. Migration: Azure Migrate (hub), Azure Data Box (ship a physical device for huge offline transfers).

Identity, Access & Security

  • Microsoft Entra ID (formerly Azure AD) — cloud identity & access management.
  • Microsoft Entra Domain Services — managed domain join, group policy, LDAP, Kerberos without running domain controllers.
  • Authentication (AuthN) = proving who you are · Authorization (AuthZ) = what you're allowed to do.
  • SSO — one login for many apps · MFA — something you know + have + are · Passwordless — Windows Hello, Authenticator app, FIDO2 keys.
  • External identities — B2B (guest partners) and B2C (customers).
  • Conditional Access — grant/block based on signals: user, location, device, risk.
  • Azure RBAC — assign roles at a scope (mgmt group / subscription / RG / resource); follow least privilege.
  • Zero Trust — "never trust, always verify": verify explicitly, least privilege, assume breach.
  • Defense in depth — layered security: physical → identity → perimeter → network → compute → app → data.
  • Microsoft Defender for Cloud — security posture & threat protection across Azure, hybrid, and multicloud.
DOMAIN 03

Management & Governance

30–35% of the exam · cost, compliance, tools, monitoring

This domain is mostly "which tool does what." Nail down cost tools, governance controls, deployment tools, and the four monitoring services and you're set.

Cost Management

  • Factors affecting cost — resource type, consumption, region/geography, network traffic (ingress usually free, egress charged), subscription type.
  • Pricing Calculator — estimate cost before deploying.
  • TCO Calculator — compare on-premises vs Azure costs.
  • Microsoft Cost Management — analyze, monitor, forecast spend; set budgets & alerts.
  • Tags — name/value metadata to organize & track resources (e.g., by department or cost center).
Don't confuse thesePricing Calculator = estimate a future Azure bill. TCO Calculator = on-prem vs cloud comparison.

Governance & Compliance

  • Azure Policy — create & enforce rules (allowed regions, required tags); flags non-compliant resources.
  • Resource locks — prevent accidents: CanNotDelete (edit but not delete) and ReadOnly (view only).
  • Microsoft Purview — data governance, risk & compliance across your whole data estate.
Policy vs RBACRBAC controls who can act. Azure Policy controls what the resources are allowed to be.

Managing & Deploying

  • Azure portal — web GUI.
  • Azure Cloud Shell — browser-based shell (Bash or PowerShell).
  • Azure CLI — cross-platform command line · Azure PowerShell — PowerShell modules.
  • Azure Arc — extend Azure management to on-prem, multicloud & edge.
  • Azure Resource Manager (ARM) — the deployment/management layer every request goes through.
  • ARM templates — JSON, declarative, idempotent infrastructure-as-code · Bicep — a cleaner language that compiles to ARM.

Monitoring — the big four

ToolAnswers…
Azure Advisor"How do I improve?" — recommendations for cost, security, reliability, performance, operations.
Service Health"Is Azure itself having problems?" — outages, planned maintenance, advisories affecting you.
Azure Monitor"How are my resources performing?" — collects & analyzes telemetry.
└ Log AnalyticsQuery logs with KQL.

Advisor vs Service HealthAdvisor = advice about your setup. Service Health = status of Azure's services.

EXAM DAY

Strategy & Tips

How to actually pass on the day
01

Watch the qualifiers

Underline words like MOST, LEAST, ONLY, and NOT. Many wrong answers are only wrong because of one qualifier.

02

Master the scenarios

Most questions are "which service fits this need?" Drill IaaS/PaaS/SaaS matching and which tool solves which problem.

03

Know the hierarchy

Management group → Subscription → Resource group → Resource comes up constantly. Have it memorized.

04

Separate the look-alikes

VPN vs ExpressRoute · Pricing vs TCO Calculator · Advisor vs Service Health · Policy vs RBAC. These are classic traps.

05

Flag and move on

You have ~50 minutes. Don't stall — mark tough questions for review and come back with time to spare.

06

Eliminate, then guess

No penalty for wrong answers. Never leave a question blank; remove the obviously-wrong options first.
