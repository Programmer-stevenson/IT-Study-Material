Domain 1 • Chapter 01

Linux foundations and the filesystem

Linux is the kernel: it schedules CPU time, manages memory, controls devices, and mediates access to resources. A distribution combines it with user-space programs, package repositories, an installer, and policies. A shell interprets commands; a terminal provides the interface. The root directory / is different from the root account and its home /root.

Use /etc for host configuration, /var for changing data and logs, /home for ordinary user homes, /usr for installed programs and shared resources, and /boot for boot artifacts. /proc exposes process and kernel information; /sys exposes devices and kernel objects. They are virtual interfaces, not ordinary disk directories. /dev contains device nodes. Many modern systems merge /bin and /sbin into /usr through symbolic links.

Know x86_64 versus AArch64 and RISC-V: binaries and installation images must match the target architecture. Free software refers to user freedoms, not necessarily price. Copyleft licenses impose redistribution obligations; permissive licenses generally impose fewer. A display manager handles graphical login; a window manager or compositor manages windows. Wayland and X11 are different display architectures.

Commands to practice

cat /etc/os-release
uname -r
uname -m
ls -ld /bin /usr/bin
ls /proc
man hier
Remember: Do not treat /proc or /sys as backup data. uname identifies the kernel; /etc/os-release identifies the distribution.
Domain 1 • Chapter 02

Boot, recovery, and kernel modules

A typical boot path is firmware → bootloader → kernel plus initramfs → root filesystem → PID 1 → services. UEFI can load an EFI executable from an EFI System Partition. GRUB selects a kernel and passes command-line arguments. The initramfs provides early tools and drivers needed to find and mount the real root filesystem, including storage and encryption support.

If the kernel starts but cannot find root, inspect the root identifier, storage drivers, and initramfs. If a system reaches an emergency shell, inspect failed mounts and journal messages before reinstalling a bootloader. Keep a known-good kernel available when updating.

Modules extend kernel functionality. lsmod shows loaded modules; modinfo describes a module; modprobe loads a module with dependency handling, whereas insmod loads a specific module file without doing the same dependency resolution. depmod rebuilds dependency metadata. Persistent module loading and options belong in the distribution's configuration directories. Use dracut on many RPM systems or update-initramfs on Debian-family systems after relevant early-boot changes.

Commands to practice

cat /proc/cmdline
journalctl -b -k
systemctl --failed
lsmod
modinfo ext4
ls /etc/modprobe.d
ls /etc/modules-load.d
Remember: Regenerating GRUB configuration and reinstalling GRUB are different operations. Paths and commands depend on distro and firmware mode.
Domain 1 • Chapter 03

Hardware and device inspection

Start with inventory, then correlate kernel messages with the device experiencing trouble. lscpu describes CPU topology; lspci and lsusb enumerate buses. lsblk shows the block-device tree. Device names can change between boots, so persistent mounts should normally reference filesystem UUIDs or other stable identifiers.

A block device supports block-oriented access, such as a disk. A character device provides a stream-like interface, such as a terminal. udev applies rules as devices appear and can create stable symlinks. dmidecode reads firmware-provided hardware tables; reported values depend on firmware accuracy. Sensors and ipmitool may expose temperatures, fan status, and out-of-band management information when supported.

A device visible on PCI but absent from the expected application can indicate a missing driver, firmware issue, permissions problem, or unsupported hardware. Inspect before replacing components. In VMs, virtual device models and VirtIO drivers matter as much as physical bus inventory.

Commands to practice

lscpu
lspci -nnk
lsusb
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS,MODEL
sudo dmesg --level=err,warn
sudo dmidecode -t memory
udevadm info --query=property --name=/dev/sda
Remember: /dev/sda is only an example for inspection. Never assume it is an expendable disk.
Domain 1 • Chapter 04

Disks, filesystems, and persistent mounts

A partition divides a disk; a filesystem organizes files within a block device; a mount attaches that filesystem to the directory tree. They are separate layers. Formatting creates filesystem metadata and can destroy access to previous data. Inspect lsblk and blkid before any change.

ext4 is a widely used journaling filesystem. XFS is common for large Linux workloads and supports online growth, but not shrinking. Btrfs supports features such as subvolumes, checksums, and snapshots. tmpfs uses virtual memory and may use swap; it is not persistent storage.

/etc/fstab describes persistent mounts. Its fields are source, mountpoint, filesystem, options, dump flag, and fsck pass. UUIDs are useful sources. Test edits before rebooting. nofail allows boot to continue when an optional mount fails; it is inappropriate as a way to hide critical storage failures. noexec, nosuid, and nodev reduce specific risks but are not complete application sandboxes.

Commands to practice

lsblk -f
sudo blkid
findmnt /
df -hT
df -i
findmnt --verify --verbose
# After reviewing a deliberate fstab change:
sudo systemctl daemon-reload
sudo mount -a
Remember: mount -a changes mount state. Filesystem repair normally requires an unmounted filesystem and the correct filesystem-specific tool.
Domain 1 • Chapter 05

LVM, RAID, swap, and capacity

LVM separates physical storage from logical allocation: a physical volume (PV) contributes space to a volume group (VG), and a logical volume (LV) consumes VG space. The filesystem lives above the LV. Extending a partition, extending a PV, extending an LV, and growing a filesystem are distinct actions; determine which layer is full.

For an ext4 LV, grow the LV and then use resize2fs, or use an appropriate supported resize option. For mounted XFS, xfs_growfs takes the mountpoint. Shrinking is far riskier and filesystem-dependent: reducing the LV before shrinking a supported filesystem can destroy data. LVM snapshots consume space as blocks change and are not independent backups.

RAID 0 stripes without redundancy; RAID 1 mirrors; RAID 5 tolerates one member failure; RAID 6 tolerates two; RAID 10 combines mirrored sets with striping and its failure tolerance depends on which disks fail. RAID does not protect against deletion or ransomware. Swap provides backing for evicted anonymous memory; excessive sustained swapping can indicate memory pressure.

Commands to practice

sudo pvs
sudo vgs
sudo lvs -a -o +devices
cat /proc/mdstat
swapon --show
free -h
# Example only: existing lab LV and confirmed free VG capacity
# sudo lvextend -L +1G /dev/labvg/data
# sudo resize2fs /dev/labvg/data
Remember: Growth examples are commented intentionally. Confirm your actual LV and filesystem before executing them.
Domain 1 • Chapter 06

Networking and persistent configuration

Troubleshoot from link state through addressing, routes, name resolution, transport, and application behavior. ip link shows interface state; ip address shows addresses and prefixes; ip route shows routing decisions. A default route is used when no more-specific route matches. A host can have a valid address but no useful gateway.

Temporary ip commands usually do not survive restart. NetworkManager connection profiles or Netplan configuration provide persistence on systems using those tools. Netplan generates configuration for a renderer such as networkd or NetworkManager. Use netplan try where appropriate to reduce remote lockout risk. Learn your interface and profile names before modifying them.

/etc/nsswitch.conf controls name-service lookup order. /etc/hosts supplies local mappings. /etc/resolv.conf may be managed by another service or be a symlink; editing it blindly can be temporary or ineffective. dig asks DNS directly, while getent hosts follows the system name-service path. A successful ping does not prove a web service is available, and blocked ICMP does not prove a server is down.

Commands to practice

ip -br link
ip -br address
ip route
ip route get 192.0.2.10
getent hosts example.com
dig example.com
resolvectl status
nmcli connection show
ss -lntup
Remember: NetworkManager, Netplan, and systemd-resolved are not installed or active on every distribution. Use the active configuration manager.
Domain 1 • Chapter 07

Shell navigation, quoting, and redirection

The shell expands variables, globs, and substitutions before invoking a program. Quote variable expansions such as "$file" to preserve spaces and prevent unwanted wildcard interpretation. Single quotes preserve literal text; double quotes still allow variable and command substitution. An absolute path begins at /; relative paths depend on the current directory. ~ is a shell expansion for a home directory.

File descriptors 0, 1, and 2 conventionally mean stdin, stdout, and stderr. > truncates or creates a file; >> appends. A pipe connects stdout of one command to stdin of the next. It does not automatically include stderr. Redirections are evaluated in order: command >out 2>&1 differs from command 2>&1 >out.

Use man and --help before guessing flags. In Vim, i enters insert mode; Escape returns to normal mode; :wq saves and exits; :q! discards changes. PATH controls command lookup, but adding writable directories to it can create security risks. Sourcing a script runs it in the current shell; executing it normally creates a separate process environment.

Commands to practice

pwd
printf '%s
' "$HOME"
printf 'alpha
beta
' > sample.txt
cat sample.txt | wc -l
ls /missing-path > output.txt 2> errors.txt
printf '%s
' 'literal $HOME'
type printf
man bash
Remember: sudo command > protected-file does not elevate the shell redirection. Use an appropriate privileged writer such as sudo tee after reviewing the intended change.
Domain 1 • Chapter 08

Text processing and reliable pipelines

Use grep to select matching lines, cut for simple delimiter-based fields, awk for field-aware processing, and sed for stream substitutions. sort orders data; uniq counts or collapses adjacent duplicates, so sorting is often required first. Regex syntax is not shell wildcard syntax: grep uses regular expressions, while the shell expands glob patterns.

Prefer small pipelines whose intermediate output you can inspect. For filenames, newline-separated parsing breaks when names contain unusual characters. find -print0 with xargs -0 preserves filename boundaries. GNU xargs -r avoids launching the command for empty input. Avoid parsing ls in scripts.

A pipeline normally reports the status of its final command. Bash pipefail changes that to the rightmost failing status, or zero when all succeed. It is useful for detecting upstream failure, but scripts must still handle expected nonzero statuses. grep returning 1 means no matches, which is not necessarily an operational failure.

Commands to practice

printf 'warn
error
warn
' > events.txt
grep -n 'warn' events.txt
sort events.txt | uniq -c
awk -F: '{print $1}' /etc/passwd
sed 's/warn/WARNING/g' events.txt
find . -maxdepth 1 -type f -name '*.txt' -print0 | xargs -0 -r wc -l
set -o pipefail
Remember: Quote find patterns so the shell does not expand them before find receives them.
Domain 1 • Chapter 09

Backups, archives, and restores

A backup is useful only when restoration is possible. Define the data, required metadata, recovery point objective (acceptable loss window), and recovery time objective (restoration time). Keep independent copies and test recovery into a separate directory or system. A snapshot on the same failing storage is not sufficient protection.

tar combines files into an archive; gzip, bzip2, and xz compress streams. rsync transfers changed data efficiently and its source trailing slash changes whether directory contents or the directory itself is copied. Preview with --dry-run and itemized changes before using deletion options. Preserve ownership, ACLs, extended attributes, and SELinux context where the recovery requirement calls for them; ordinary archive options do not always preserve every attribute.

For a failing physical disk, repeated reads may worsen failure. ddrescue is designed to recover readable regions with a mapfile and resumable attempts. dd is a raw copying tool with no awareness of filesystems; a reversed input/output can overwrite the wrong disk. Database backups may require application-aware consistency beyond a filesystem copy.

Commands to practice

mkdir -p "$HOME/linuxplus-lab/source" "$HOME/linuxplus-lab/restore"
printf 'backup test
' > "$HOME/linuxplus-lab/source/note.txt"
tar -czf "$HOME/linuxplus-lab/notes.tar.gz" -C "$HOME/linuxplus-lab/source" .
tar -tzf "$HOME/linuxplus-lab/notes.tar.gz"
tar -xzf "$HOME/linuxplus-lab/notes.tar.gz" -C "$HOME/linuxplus-lab/restore"
diff "$HOME/linuxplus-lab/source/note.txt" "$HOME/linuxplus-lab/restore/note.txt"
Remember: Do not extract an unfamiliar archive as root over an existing filesystem. Inspect its contents and restore to a separate directory.
Domain 1 • Chapter 10

Virtualization and cloud images

A VM has its own kernel and virtual hardware. KVM supplies Linux virtualization capabilities; QEMU supplies virtual machine emulation and device models; libvirt offers a management layer. VirtIO drivers reduce overhead through virtualization-aware interfaces.

NAT networking allows outbound access through the host; bridged networking places a guest on an attached network; isolated networks restrict connectivity to a defined virtual segment. Bridging to a workplace network may expose an experimental guest, so use NAT plus an isolated lab network for study.

Disk image growth does not automatically extend the guest partition or filesystem. Thin-provisioned images can report a large logical size while initially consuming less host storage; monitor actual backing capacity. Snapshot chains and clones need lifecycle management. Cloud-init applies first-boot configuration on images that support it. Templates must not leak private keys or duplicate machine identity. A cloud image still needs updates, least-privilege access, and a recovery plan.

Commands to practice

virsh list --all
virsh dominfo lab-server
virsh domblklist lab-server
virsh net-list --all
qemu-img info lab-server.qcow2
cloud-init status --long
Remember: These commands require the relevant virtualization tools and existing lab objects. Do not modify an active disk image with qemu-img.
Domain 2 • Chapter 11

Files, directories, links, and search

A directory maps names to inode references. A hard link is another name for the same inode on the same filesystem; deleting one name does not delete the content while other links or open references remain. A symbolic link stores a path and can cross filesystems, point to directories, or become dangling.

Use stat to inspect metadata and ls -li to compare inode numbers. find searches current filesystem state; locate searches a database that may be stale. find predicates combine path, type, owner, time, size, and other properties. Preview matches before adding deletion or execution actions.

Copying data does not always copy all metadata. cp -a attempts archive-style preservation, while ordinary cp has different defaults. mv within a filesystem usually renames directory entries; crossing filesystems can require copying and removing. File extension is a convention, not definitive proof of content: file examines signatures. lsof can expose which process keeps a supposedly deleted file open.

Commands to practice

mkdir -p "$HOME/linuxplus-lab/links"
cd "$HOME/linuxplus-lab/links"
printf 'same inode
' > original.txt
ln original.txt hard.txt
ln -s original.txt symbolic.txt
ls -li
stat original.txt
find . -type f -name '*.txt' -print
Remember: Hard links generally cannot cross filesystem boundaries. A symlink target may be interpreted relative to the directory containing the symlink.
Domain 2 • Chapter 12

Users, groups, and account lifecycle

The kernel uses numeric UIDs and GIDs for ownership and access checks. Names are resolved through configured account databases. /etc/passwd records local identity fields, while /etc/shadow contains protected password hashes and aging data. getent queries the configured name-service sources and can include directory identities.

useradd behavior varies with defaults; -m explicitly creates a home on common implementations. Supplementary groups provide access beyond the primary group. usermod -aG appends membership; omitting -a can replace existing supplementary memberships. Existing sessions may keep old group credentials until a new login.

Password locking blocks password authentication but may not disable SSH keys, scheduled jobs, active sessions, or external authentication. Offboarding requires an access review across those paths. Use account expiration, key revocation, session termination, and service ownership transfer as appropriate. Service accounts normally have restricted interactive access and own application-specific files, not broad administrator rights.

Commands to practice

id
getent passwd "$USER"
getent group
sudo useradd -m -s /bin/bash labuser
sudo passwd labuser
sudo groupadd labteam
sudo usermod -aG labteam labuser
id labuser
sudo chage -l labuser
Remember: Account-changing examples are for a disposable VM. Do not confuse locking a password with disabling every authentication method.
Domain 2 • Chapter 13

Processes, signals, jobs, and priorities

A process has a PID, parent PID, credentials, memory mappings, open files, and a state. Running/runnable processes compete for CPU; sleeping processes wait; stopped processes are suspended; zombies have exited but their parent has not collected their status. A zombie cannot be fixed by killing its already-exited body; investigate the parent.

SIGTERM requests graceful termination and can be handled. SIGKILL cannot be caught and prevents normal cleanup. A task in uninterruptible sleep may not disappear immediately even after SIGKILL because it is waiting in the kernel. Diagnose blocked I/O instead of repeatedly sending signals.

Ctrl+C sends an interrupt to a foreground job; Ctrl+Z suspends it. bg resumes a stopped job in the background; fg returns it to the foreground. nohup changes hangup handling but is not a service supervisor. Lower nice values indicate higher scheduling priority; raising priority generally requires privilege. A high load average may reflect runnable tasks or uninterruptible waits, so compare load to CPU count and I/O indicators.

Commands to practice

ps -eo pid,ppid,stat,ni,%cpu,%mem,comm --sort=-%cpu | head
pgrep -a sshd
top
sleep 120 &
jobs
# Stop only the background job started above:
kill -TERM "$!"
ulimit -n
Remember: Use a confirmed PID and inspect the target before sending signals. killall and pkill can affect multiple processes.
Domain 2 • Chapter 14

Packages, repositories, and software provenance

A high-level package manager resolves dependencies and consults repositories; lower-level tools inspect or manipulate package files and the installed database. Debian-family systems commonly use apt with dpkg; RPM-family systems commonly use dnf with rpm. apt update refreshes repository metadata, while apt upgrade changes installed packages.

Signed repository metadata and packages provide provenance and integrity checks when used with trusted signing keys. Importing an arbitrary key makes that trust decision meaningful; disabling signature verification removes protection. Pinning, exclusions, and version holds can preserve compatibility but also delay security fixes.

Use the package manager to identify who owns a file before replacing it manually. Investigate dependency conflicts through configured repositories and package versions rather than forcing installations. Language packages belong in appropriate environments: Python virtual environments avoid overwriting distribution-managed Python. Source builds need a plan for updates, ownership, and removal. Sandboxed formats such as Flatpak or Snap have separate permissions and update models.

Commands to practice

# Debian / Ubuntu
apt-cache policy bash
dpkg -S /bin/bash
dpkg -l bash
# RPM family
rpm -q bash
rpm -ql bash
dnf info bash
# Isolated Python environment
python3 -m venv "$HOME/linuxplus-lab/venv"
Remember: Paths may resolve through /usr on merged systems. Package database ownership queries can require the canonical path.
Domain 2 • Chapter 15

systemd services, targets, and timers

A unit represents a resource managed by systemd. Services manage processes; targets group units; timers schedule activation; mount units manage mounts. start changes current state. enable configures activation relationships for future boots or other triggers; it does not necessarily start the service unless --now is included. disable does not stop an already running service by itself. mask prevents normal activation until unmasked.

After editing unit definitions, daemon-reload reloads systemd's unit configuration. reload asks the application to reload its own configuration if supported; restart stops and starts it. These actions solve different problems. Prefer drop-in overrides via systemctl edit over modifying packaged unit files.

A service can be active without being reachable or healthy. Combine status, journal output, listener checks, and an actual request. Timers can be calendar-based or monotonic. Persistent=true on a calendar timer can catch up a missed activation when the timer becomes active; it does not replay every missed interval separately.

Commands to practice

systemctl --failed
systemctl list-unit-files --type=service
systemctl status sshd
systemctl cat sshd
journalctl -u sshd -b --no-pager
systemctl list-timers --all
systemd-analyze critical-chain
Remember: The SSH unit is commonly ssh on Debian/Ubuntu and sshd on RPM systems. Use the name your distribution provides.
Domain 2 • Chapter 16

Core services and job scheduling

Recognize the role of each service before troubleshooting it. DNS resolves names and serves zone data. DHCP leases addressing information. HTTP servers serve requests or reverse-proxy to applications. SMTP transfers mail; IMAP provides mailbox access. NTP synchronizes clocks, while PTP can support more precise synchronization in suitable environments. Clock accuracy matters for logs, certificates, and Kerberos.

Check configuration syntax before reloading services: nginx -t or the relevant Apache test command catches many failures without taking down a working process. Separate listening address, port, document root, upstream endpoint, and TLS configuration in your diagnosis.

Cron expresses minute, hour, day-of-month, month, and day-of-week fields. User crontabs omit a username field; /etc/crontab includes one. Jobs often run with a smaller environment than an interactive shell, so use explicit paths and capture errors. anacron supports periodic tasks on machines not always running. at schedules a one-time job. systemd timers provide another approach with integrated service logging.

Commands to practice

timedatectl
chronyc tracking
sudo nginx -t
curl -I http://127.0.0.1
crontab -l
# Example user-crontab line, not a shell command:
# 15 2 * * * /home/labuser/bin/report.sh >> /home/labuser/report.log 2>&1
Remember: Time-service commands require the corresponding implementation. Cron day-of-month/day-of-week matching has implementation-specific rules; do not assume both restricted fields must match.
Domain 2 • Chapter 17

Containers, images, and persistence

A Linux container is an isolated process environment sharing the host kernel. An image supplies the filesystem template; a container adds runtime state and a writable layer. Deleting the container can discard that layer. Named volumes or deliberate bind mounts persist data independently of the container lifecycle.

Understand host-port:container-port mapping. Binding a published port to 127.0.0.1 restricts normal remote access to that host listener. A container can run while its application is unhealthy, so inspect logs and test a request. Rootless Podman reduces dependence on a root daemon, but containers are not a substitute for host security.

Dockerfile FROM chooses the base, COPY adds files, RUN builds layers, USER chooses runtime identity, and ENTRYPOINT/CMD define default startup behavior. Tags can move; digests identify image content more precisely. Avoid embedding secrets in image layers. Use capabilities and restricted mounts instead of --privileged. On SELinux hosts, volume labels must be appropriate; :Z and :z have distinct private/shared labeling implications.

Commands to practice

# Podman installed; internet needed for first pull
podman run -d --name linuxplus-web -p 127.0.0.1:8080:80 docker.io/library/nginx:alpine
podman ps
podman logs linuxplus-web
curl -I http://127.0.0.1:8080
podman inspect linuxplus-web
podman stop linuxplus-web
podman rm linuxplus-web
Remember: Image tags change over time. Use a reviewed digest for repeatable deployments. Do not prune unknown volumes; they may contain application data.
Domain 3 • Chapter 18

Permissions, ACLs, and special modes

Permissions apply to owner, group, and others using read=4, write=2, execute=1. For files, execute allows execution; for directories, execute permits traversal, read permits listing names, and write permits changing entries. Removing a file is primarily governed by the containing directory's permissions, with sticky-bit and other restrictions also relevant.

umask removes permission bits from a program's requested creation mode; it is a bitmask, not general decimal subtraction. A usual file request of 666 with umask 027 yields 640; a directory request of 777 yields 750. umask does not grant execute bits that an application never requested.

Setgid on a shared directory makes new entries inherit the directory group. Sticky directories such as /tmp restrict who can remove or rename entries. Setuid on a suitable executable changes effective UID during execution and requires careful review. ACLs grant additional named-user/group access; the ACL mask caps effective permissions for named users and the group class. Default ACLs on directories affect newly created descendants, not existing files retroactively.

Commands to practice

mkdir -p "$HOME/linuxplus-lab/permissions"
cd "$HOME/linuxplus-lab/permissions"
touch report.txt
chmod 640 report.txt
stat -c '%a %U %G %n' report.txt
umask
getfacl report.txt
namei -l "$HOME/linuxplus-lab/permissions/report.txt"
Remember: chmod 777 is not a troubleshooting strategy. Inspect parent traversal, ownership, ACL masks, and mandatory access controls.
Domain 3 • Chapter 19

Authentication, sudo, and SSH hardening

Authentication verifies identity; authorization determines allowed actions; accounting records activity. PAM provides application authentication/session stacks. SSSD can integrate Linux with directory identity systems. LDAP is a directory protocol; Kerberos provides ticket-based authentication and depends on correct time and naming.

Use sudo for scoped elevation and validate sudoers edits with visudo. Broad permission to run an editor, interpreter, package manager, or writable script as root can effectively grant full root access. NOPASSWD removes a password prompt, not the need to constrain privileges. Polkit authorizes privileged actions exposed by cooperating services.

SSH uses host keys to authenticate the server and user credentials to authenticate the client. Verify unexpected host-key changes instead of deleting known_hosts entries reflexively. Protect private keys with file permissions and preferably a passphrase. Validate sshd configuration, maintain a working session and console recovery path, and test a second login before disabling password access. Effective configuration can differ because of include files and Match blocks.

Commands to practice

sudo -l
sudo visudo -c
ssh-keygen -t ed25519 -f "$HOME/.ssh/linuxplus_lab"
# Inspect and validate the server configuration:
sudo sshd -t
sudo sshd -T | head
ls -ld "$HOME/.ssh"
ssh -v labuser@192.0.2.10
Remember: 192.0.2.10 is a documentation placeholder. Replace it with your lab host. Never share private keys or paste them into a repository.
Domain 3 • Chapter 20

SELinux, AppArmor, and layered hardening

Traditional Unix permissions are discretionary access control. SELinux adds label-based mandatory access controls; AppArmor commonly applies path-oriented application profiles. A file readable under chmod can still be denied by policy. Identify the actual denial instead of turning security enforcement off as a permanent fix.

SELinux enforcing blocks violations, permissive logs policy violations without enforcing them, and disabled means SELinux is not active. ls -Z shows labels; getenforce shows mode. restorecon applies expected labels. semanage fcontext manages persistent path-label mappings; chcon changes a label directly and can be undone by relabeling. Booleans enable defined policy behaviors; review their purpose before changing them.

Minimize installed services, apply updates, protect management access, and review capabilities. chattr +i can prevent ordinary changes on supporting filesystems, but privileged users can remove the attribute. Full-disk encryption protects data at rest when locked; it does not prevent a logged-in privileged process from reading mounted data. LUKS management must include recovery keys and tested access procedures.

Commands to practice

getenforce
ls -Z /var/www
sudo ausearch -m AVC -ts recent
sudo restorecon -nRv /var/www
sudo aa-status
getcap /usr/bin/ping
lsattr /etc/hosts
Remember: Commands apply only where the relevant security framework is installed. restorecon -n previews; do not generate broad allow policies blindly from logs.
Domain 3 • Chapter 21

Firewalls, ports, and secure networking

A listening service, a local firewall, a network firewall, routing, and application authorization are separate controls. Diagnose each layer. nftables is a framework for packet filtering; firewalld and UFW provide higher-level administration. Avoid mixing rule managers without understanding who owns and rewrites the rules.

Stateful filtering can recognize established connections; stateless filtering evaluates packets without that connection context. In firewalld, zones associate policy with interfaces or sources. Runtime and permanent configurations differ: a runtime-only change can disappear at reload, and a permanent-only change may not yet be active.

NAT rewrites addresses; SNAT changes a source and DNAT changes a destination. Port translation can map different transport ports. Forwarding must be enabled when the host routes packets, but enabling forwarding alone does not create routes or permit firewall traffic. Before tightening access over SSH, allow the verified management source and maintain console access. Test both permitted and denied flows.

Commands to practice

ss -lntup
sudo nft list ruleset
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all
sudo firewall-cmd --permanent --list-all
sudo ufw status verbose
sysctl net.ipv4.ip_forward
Remember: These are alternative toolchains, not instructions to enable all firewall managers. Container publishing can interact with host firewall rules.
Domain 3 • Chapter 22

Logs, auditing, cryptography, and integrity

Collect evidence with timestamps, host identity, and a clear scope. journalctl queries systemd journal data; rsyslog can process and forward logs; logrotate manages rotation policies for text logs. Audit records focus on security-relevant events such as file access or privileged actions. Logs must be protected and retained appropriately because attackers and accidental changes can erase local evidence.

A cryptographic hash detects changes relative to a known value but does not authenticate the publisher. A signature combines integrity verification with an identity trust decision. Encryption protects confidentiality; hashing is not reversible encryption. TLS requires validating the certificate chain, validity period, and hostname. Time drift can cause certificate or authentication failures.

Do not place secrets in logs, shell history, environment dumps, or Git commits. Use redaction when sharing diagnostics. For incident response, record observations, preserve relevant evidence, limit exposure, and use known-good recovery processes. Restarting or deleting logs immediately can destroy the information needed to understand the fault.

Commands to practice

journalctl -b -p warning --no-pager
journalctl --since '1 hour ago' --no-pager
journalctl --disk-usage
sudo auditctl -s
sha256sum /etc/hosts
openssl x509 -in certificate.pem -noout -subject -issuer -dates
sudo logrotate --debug /etc/logrotate.conf
Remember: certificate.pem is an example file you must supply. logrotate --debug reports intended actions without rotating logs.
Domain 4 • Chapter 23

Bash scripting and defensive automation

A script should declare its interpreter, validate inputs, handle failure, and communicate results through exit status. Zero normally indicates success. Use "$@" to forward arguments without merging them; $? holds the last command status and is overwritten by subsequent commands. Use $(command) for command substitution and quote the result where appropriate.

Test file properties with [[ -f path ]] or [[ -d path ]] in Bash. Use numeric operators appropriate to the test context. Loops, case statements, and functions make workflows reusable. Prefer read -r for literal line input. Avoid eval on untrusted strings and avoid building commands by string concatenation.

set -e is not universal error handling: exceptions in conditional and pipeline contexts can surprise you. Explicitly checking important commands is clearer. Use trap for cleanup of temporary resources, mktemp for temporary names, and meaningful stderr messages. bash -n checks syntax but not behavior; ShellCheck can identify additional issues. Test scripts with empty input, spaces, permission denial, missing commands, and partial failure.

Commands to practice

#!/usr/bin/env bash
# Save as check-path.sh, then run: bash check-path.sh /etc/hosts
set -u
if [[ $# -ne 1 ]]; then
  printf 'Usage: %s PATH
' "$0" >&2
  exit 2
fi
if [[ -r "$1" ]]; then
  printf 'Readable: %s
' "$1"
else
  printf 'Not readable: %s
' "$1" >&2
  exit 1
fi
Remember: Bash-specific [[ ... ]] is not portable POSIX sh syntax. Match your shebang to your language features.
Domain 4 • Chapter 24

Git, configuration data, and APIs

Git tracks snapshots of project content. The working tree contains your edits; the index stages the next commit; commits record history. Review git diff and git diff --staged before committing. A branch is a movable reference to a commit. fetch updates remote-tracking information; pull incorporates fetched changes according to configuration; push publishes local commits.

Use .gitignore for generated outputs and secrets that have never been tracked. It does not remove already tracked files or erase history. If a secret is committed, revoke or rotate it before addressing repository history. Prefer reviewable changes, small commits, and tested rollback plans.

JSON, YAML, and XML are structured formats. YAML indentation is significant and tabs are unsuitable for indentation. jq parses JSON; avoid scraping JSON with grep. HTTP methods have different semantics: GET retrieves, POST commonly creates/actions, PUT commonly replaces, PATCH changes part of a resource, and DELETE removes. Check status codes and application response content. Store API credentials outside public code and avoid printing them in debug logs.

Commands to practice

git status
git diff
git diff --staged
git log --oneline -5
printf '{"host":"lab","healthy":true}
' | jq '.host'
curl --fail --show-error --silent https://example.com/ -o /tmp/linuxplus-example.html
Remember: A successful HTTP transport response does not always mean the application operation succeeded; inspect the documented response schema.
Domain 4 • Chapter 25

Ansible and infrastructure as code

Configuration management describes desired state and converges machines toward it. Idempotency means repeating an operation produces the same intended state without unnecessary changes. Ansible uses inventories to select hosts and playbooks to organize tasks; modules perform specific operations. Handlers run when notified by changed tasks, making service restarts more deliberate.

Use modules such as file, package, and service instead of shell commands when they model the task. Check mode previews supported changes, but not every module/action can be simulated completely. Review diffs carefully because rendered templates can include sensitive values. Separate variables by environment and protect secrets with an appropriate secret store or encrypted mechanism.

Infrastructure provisioning tools manage resources such as instances and networks; configuration management handles state inside hosts. State files may contain sensitive data and must be secured and coordinated. Review a plan before applying changes, pin dependencies deliberately, and detect drift. IaC still requires backups, access control, peer review, and an understanding of the resources it can replace.

Commands to practice

# Save as lab.yml; requires Ansible on the local control host.

- name: Create a local study directory
  hosts: localhost
  connection: local
  gather_facts: false

Domain 4 • Chapter 26

Orchestration, pipelines, and observability

Container orchestration schedules workloads, manages desired replica counts, and coordinates networking and recovery. In Kubernetes, a Pod is a scheduling unit for one or more closely related containers. A Deployment manages replicated Pods through ReplicaSets; a Service provides a stable access abstraction. ConfigMaps hold non-secret configuration. Secrets need access controls and appropriate at-rest protection; base64 representation alone is not encryption.

Readiness determines whether a workload should receive traffic. Liveness can trigger restarts. A poorly designed liveness probe can turn a dependency outage into a restart storm. Resource requests guide scheduling; limits constrain consumption. Diagnose events and application logs rather than assuming every Pending Pod is a broken image.

A CI/CD pipeline validates changes through stages such as linting, tests, builds, scanning, and deployment. Promote known artifacts and retain rollback capability. Metrics show trends, logs show events, and traces connect work across services. A service-level indicator measures behavior; a service-level objective states a target. Alerts should reflect actionable impact. Review generated automation, including AI-assisted output, before granting it privileges or production access.

kubectl config current-context
kubectl get pods
kubectl get deployments
kubectl get services
kubectl get events --sort-by=.metadata.creationTimestamp
# Substitute a real lab Pod name:
# kubectl describe pod POD_NAME

Domain 5 • Chapter 27

A repeatable troubleshooting method

Begin with impact, scope, timeline, and the last known-good state. Separate symptoms from causes: a timeout is an observation, not proof of a firewall failure. Establish a hypothesis, choose a low-risk test that distinguishes it from alternatives, and record the result. Change one relevant variable at a time.

Collect host, version, uptime, recent changes, configuration, logs, and resource evidence. Compare a working path to a failing path. Test locally before remotely when isolating an application problem. Understand whether the failure is persistent, intermittent, load-related, or limited to a user/network.

Mitigation restores service; root-cause correction prevents recurrence. They may be different actions. Keep a rollback path, validate the original user workflow, and monitor after repair. Document symptoms, evidence, cause, change, validation, and follow-up. Avoid destructive cleanup merely to make an error disappear. A reboot can restore availability while removing the transient evidence you needed.

Commands to practice

date -Is
uptime
cat /etc/os-release
systemctl --failed
journalctl -b -p err --no-pager
df -h
free -h
ip -br address
Remember: Collect only what you need and redact sensitive data before sharing. Do not treat a single metric as a root cause.
Domain 5 • Chapter 28

CPU, memory, and I/O diagnosis

Compare demand with capacity and establish a baseline. High CPU use can be productive work; high latency can also come from I/O, locks, network waits, or downstream services. ps identifies heavy processes, top shows changing state, and pidstat can provide per-process intervals. In virtual machines, CPU steal suggests time taken by the hypervisor for other work.

Linux uses otherwise idle RAM for caches. Low free memory alone is not proof of exhaustion; consider available memory, swap activity, pressure, and OOM records. A memory leak tends to show growth over time under a comparable workload. Containers can hit cgroup limits while the host still has free RAM.

For storage, use iostat when installed and correlate queueing, latency, throughput, and workload. A percentage near 100% device utilization is not a universal saturation verdict for modern parallel storage. vmstat's first report is often an average since boot; later interval reports describe the interval. strace reveals syscalls and errors but can expose sensitive arguments and alter timing.

Commands to practice

free -h
vmstat 1 5
ps -eo pid,comm,%cpu,%mem --sort=-%mem | head
cat /proc/pressure/memory
journalctl -k -b | grep -i 'out of memory\|oom'
iostat -xz 1 3
pidstat 1 3
Remember: sysstat tools may need installation. Interpret multiple samples rather than one snapshot.
Domain 5 • Chapter 29

Storage, boot, and permissions failures

A no-space error can mean exhausted blocks, exhausted inodes, quotas, or a different full mount than expected. Compare df with du and check the actual mountpoint. Deleted-but-open files can account for a large discrepancy; lsof +L1 helps find them. Avoid deleting arbitrary application files to reclaim space.

For read-only filesystem errors, inspect mount options and kernel messages. The kernel may remount a damaged filesystem read-only to protect it. Do not immediately force read-write and continue a failing workload. Plan backup/recovery and offline filesystem-specific repair as appropriate.

For permission denied, identify the process identity and walk every directory component. Check owner/mode, supplementary groups, ACL mask, mount options, immutable flags, and SELinux/AppArmor denials. Running as root can hide rather than solve the problem. For boot failures after storage changes, inspect fstab identifiers, device availability, encryption/LVM activation, initramfs content, and bootloader arguments. Keep console access and recovery media available.

Commands to practice

df -hT
df -i
findmnt -T /var/log
sudo du -xhd1 /var/log
sudo lsof +L1
namei -l /var/log
journalctl -k -b -p warning
findmnt --verify --verbose
Remember: Do not run a generic fsck against a mounted filesystem or use the wrong repair utility for XFS/Btrfs.
Domain 5 • Chapter 30

Network and application incident isolation

Distinguish timeout, refused connection, name-resolution failure, TLS failure, and application error. A refusal often indicates no listener or an explicit reject. A timeout can reflect filtering, path failure, overload, or a silent peer. Do not assign a cause from the symptom alone.

Test the listener locally, its bound address, the selected route, and remote reachability. A service on 127.0.0.1 is not normally reachable via the external interface. DNS failure with working IP connectivity points toward resolution but may also involve application-specific name handling. TLS errors require checking hostname, trust chain, and time, not simply disabling verification.

Packet capture can reveal whether SYN packets arrive and whether responses leave. Scope captures by interface, host, port, and count to avoid collecting unnecessary data. Check MTU when small requests work but larger transfers stall. For container incidents, inspect port mapping, container logs, service binding inside the container, volume permissions, and host firewall interaction. Verify the final application response after fixing infrastructure.

Commands to practice

ss -lntp
curl -v --connect-timeout 5 http://127.0.0.1:8080
getent hosts example.com
ip route get 192.0.2.10
ip -s link
# Lab-only, bounded capture; replace interface if needed:
sudo tcpdump -ni any -c 20 'tcp port 8080'
# Inspect TLS without bypassing certificate checks:
curl -I https://example.com
Remember: Use only networks you administer for scans/captures. curl -k hides certificate-validation problems rather than correcting them.
